<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → /api/cron/* | Unauthenticated callers can hit cron routes; only a matching Bearer CRON_SECRET should run the job. |
| Job → Supabase Storage + DB | Service-role job deletes Storage objects + mutates audio_clips across all teachers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 (T-CRON-AUTH) | Elevation of Privilege | /api/cron/mark-missed, /api/cron/purge-audio | mitigate | Both routes verify `Authorization: Bearer ${CRON_SECRET}` and return 401 immediately if absent/mismatched; the `!cronSecret` check blocks the unset-secret case (RESEARCH Security Domain). |
| T-07-10 (T-STORAGE-ORDER) | Tampering | purgeExpiredAudio | mitigate | Storage `.remove()` is called before the DB update so no Storage object is orphaned; rows are marked deleted (not row-deleted), preserving the transcript audit trail. |
| T-07-11 | Tampering | duplicate cron invocation | mitigate | markMissedAssignments conditionally transitions only assigned/started rows; purge filters `.neq("processing_status","deleted")` — re-runs skip already-processed rows (idempotent; RESEARCH Pitfall 5). |
| T-07-12 | Information Disclosure | structured logger | mitigate | Logger context fields carry ids (clipId/attemptStudentId) not transcript text or PII; instrumentation table fields are id/count/error-message only. |
| T-07-SC | Tampering | npm installs | accept | No new packages installed in this plan (RESEARCH audit); logger is zero-dependency. |
</threat_model>
