## Typography

All sizes in px. Line heights as ratios. Weights use numeric values only.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / transcript | 16px | 400 | 1.5 |
| Label / meta / badge | 14px | 600 | 1.4 |
| Subheading (Turn N, section titles) | 20px | 600 | 1.25 |
| Page title (h1) | 28px | 600 | 1.2 |

**Source:** Extracted exactly from existing teacher page inline styles. No new sizes or weights are introduced in Phase 7.

Rules:
- Body copy (transcripts, review reason text, empty state copy): 16px / 400 / lh 1.5
- Label text above a value (e.g. "Student", "Mission", "Status"): 14px / 600 / color #4B5563
- Meta text (submitted time, student count, assignment due date): 14px / 400 / color #4B5563
- Navigation links and CTA-style links (e.g. "Review", "← Classes"): 14px / 600 / color #2563EB
- Status badge text: 12px / 600 (only exception below body — kept compact for inline scan badges)

### Destructive and Irreversible Actions

Phase 7 has **no permanently destructive student-visible actions** (audio purge is a background job, not teacher-triggered). The override actions are reversible (teacher can re-override). Confirmation dialogs are required per D-09 but are not destructive-deletion flows.

Override confirmation approach: inline modal dialog (not a full-page redirect). Show after button click. Require explicit "Confirm" before the server action fires. Display reason-note field in the modal before confirm.

## Interaction Contracts

### Assignment List Row (Review Dashboard)

- Entire row is clickable (link to per-assignment bucket view)
- "View results" text link is the explicit CTA on the right
- Hover state: card background shifts to #F9FAFB (one step lighter — sufficient contrast)
- No hover state on the row container itself; only the "View results" link shows underline on hover

### Per-Student Scan Row (Bucket View)

- Each row is a `<article>` with flex layout: left = student name + status badge, right = submitted time + "Review" link
- "Review" link navigates to `/teacher/evidence/[attemptId]`
- No row-level click — only the explicit "Review" link navigates
- Row height: min 56px (matches header height — consistent touch target)

### Override Controls (Attempt Detail)

- Three buttons rendered in a horizontal group below the existing evidence sections
- Buttons are only enabled when `evidence.attemptStatus` is in a teacher-overridable state (`teacher_review`, `completed`, `started`)
- On click: open an inline confirmation dialog (not a page navigation)
- Dialog contains: heading, body copy, optional reason-note `<textarea>` (3 rows), Cancel + Confirm buttons
- On Confirm: call server action, show inline success or error feedback, refresh page data
- On Cancel: close dialog, no action
- Pending state during server action: disable all three override buttons + show "Updating..." on the Confirm button

### Status Badge

- `<span>` with `display: inline-block`, `borderRadius: 9999` (pill), `fontSize: 12`, `fontWeight: 600`, `padding: "2px 8px"`
- Not interactive — display only
- Carries the semantic color from the status badge palette table above

### Back Navigation

- All back links use `← {destination}` format (Unicode left arrow + space + label)
- `fontSize: 14`, `color: "#2563EB"`, `textDecoration: "none"`
- No hover underline on mobile; underline on desktop hover

## Accessibility Contracts

- All `<article>` elements in evidence lists carry `aria-label="{studentName} — {status}"` on the row
- Bucket sections use `<section aria-label="{bucket heading} students">`
- Override buttons carry `aria-label="Mark attempt {action}"` in addition to visible text
- Confirmation dialog: focus trapped inside while open; `role="dialog"` and `aria-labelledby` pointing to the heading; close on Escape key
- Status badge: `role="status"` is NOT used (static display, not a live update); no `aria-live` needed on badge
- "Review" links in student rows carry `aria-label="Review {studentName}'s attempt"`
