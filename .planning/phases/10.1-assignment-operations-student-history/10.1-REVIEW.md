# Phase 10.1: Code Review Report

**Reviewed:** 2026-07-13T14:39:39Z
**Depth:** standard
**Files Reviewed:** 12
**Status:** issues_found

## Summary

Reviewed the phase 10.1 assignment-operations and student-history surface: the new missed→started (late-open) transition, the review-receipt migration and RPCs, the teacher review-queue domain helpers, and the child-facing recap page/component (plan 10.1-08). All 293 unit/schema/contract tests pass, but two Critical cross-module defects survive the tests:

1. The newly legalized `missed → started` transition conflicts with the daily `markMissedAssignments` cron, which re-marks late-started work as `missed`, orphaning the student's in-progress attempt and making completion fail.
2. The recap's "Words to practice" list reintroduces the previously fixed phantom-word bug: it surfaces raw Azure error-type words (including target-sentence words the student never said) instead of using the transcript-intersected `wordsToPractice()` domain helper that the live mission flow uses.

Additional warnings cover error-path gaps in `mission-flow.ts`, a superseded RPC body still pinned by schema tests, teacher-queue visibility loss after `request_submission_retry`, and server-timezone date rendering in the recap header.

## Critical Issues

### CR-01: Daily missed-marking cron re-flips late-opened missions to `missed`, orphaning the student's in-progress attempt and breaking completion

**File:** `src/domain/foundation/status.ts:43` (missed→started legalized), `src/domain/foundation/status.ts:83-104` (`shouldMarkMissed`), `src/server/student-access/mission-flow.ts:260-296` (late-open path); interacting consumer: `src/server/foundation/markMissedAssignments.ts:16` and `src/app/api/cron/mark-missed/route.ts`
**Issue:** This phase legalizes `missed → started` so a student can open overdue homework (D-22). But `shouldMarkMissed` still returns `true` for any `started` row whose `due_at` is in the past, and the daily cron (`markMissedAssignments`) selects `.in("status", ["assigned", "started"])`. A late-opened mission is by definition past due, so the next cron run flips it straight back to `missed` while the student's attempt is still `in_progress`. Consequences, all verified against current code:
- **Resume is destroyed:** `startOrResumeAttempt` only resumes when `asRow.status === "started"` (mission-flow.ts:215). With status flipped back to `missed`, the next open falls through to step 3, inserts a *new* attempt, and repoints `latest_attempt_id` — the old `in_progress` attempt (with the student's recorded turns) is orphaned forever and never abandoned; `attempt_count` inflates. The student redoes the mission from turn 1. This loops every day the mission stays unfinished.
- **Completion fails mid-session:** `complete_student_attempt` (202607100001) requires `v_assignment_status = 'started'` and returns `not_found` otherwise. If the cron fires while the student is mid-attempt, they can keep recording turns (`recordAnswer` only checks the attempt is `in_progress`) but "Finish" fails after they have done all the work.
- **Audit noise:** each late-open cycle emits an extra `due_date_elapsed` event contradicting the immediately preceding `late_mission_started` event.
No test covers the cron × late-open interaction; `foundation-status.test.ts` only asserts the transition matrix in isolation.
**Fix:** Make the missed-marking job unable to undo a late open. Minimal, targeted fix in `markMissedAssignments`: also select `latest_attempt_id` plus the latest attempt status, and skip `started` rows whose latest attempt is `in_progress`:
```ts
// markMissedAssignments.ts — query attempts(status) via latest_attempt_id and:
const latestAttemptInProgress = row.latest_attempt_status === "in_progress";
if (row.status === "started" && latestAttemptInProgress) continue; // student actively working (incl. late-open)
```
Alternatively encode this in the domain: add `hasInProgressAttempt` to `MissedStatusInput` and return `false` for `started` rows with a live attempt, with a test asserting a late-opened (missed→started, past-due) row is NOT re-marked. Note the teacher's Incomplete queue already derives "missed" urgency from `dueAt`, not status (`groupIncompleteAssignments`), so lateness display does not depend on re-flipping the status.

### CR-02: Recap "Words to practice" resurfaces words the student never said (reintroduces the documented phantom-word bug)

**File:** `src/components/student/StudentMissionRecap.tsx:13-17`; root cause feeding it: `src/server/student-access/student-history.ts:91`
**Issue:** The label-aware feedback added in plan 10.1-08 computes `practiceWords = turn.pronunciation.words.filter((word) => word.label !== "Clear")` and renders them as "Words to practice". But the labels come from `student-history.ts`, which maps **every** raw Azure `word_scores` entry with `errorType === "None" ? "Clear" : "Keep practicing"`. Azure scores the audio against the mission's **target sentence**, so `Omission` entries are target-sentence words the student never uttered, and `Insertion`/`UnexpectedBreak`/`MissingBreak` entries are not pronunciation-practice words either. The codebase already documents and solves exactly this in `src/domain/pronunciation/scoring.ts:145` (`wordsToPractice()`): it restricts to `PRACTICE_ELIGIBLE_ERROR_TYPES` (`Mispronunciation`, `Monotone`), intersects with the student's own transcript, and caps at 3 words — and the live mission flow uses it (`audio-upload.ts:826`). The recap bypasses all of that, so the same turn can show different (and wrong) practice words in the recap than the student saw during the mission, and the list is uncapped. This directly contradicts the "words must intersect the student transcript" rule established when this bug was first fixed. The source-contract test (`student-history-ui.test.ts:40-41`) only asserts the `label !== "Clear"` filter exists, which locks in the wrong behavior.
**Fix:** Derive recap practice words through the existing domain helper instead of ad-hoc label filtering. In `getCompletedMissionRecap`, replace the inline `word_scores` mapping with:
```ts
import { wordsToPractice } from "@/domain/pronunciation/scoring";
// transcript = the same one shown in the bubble (repeat if accepted, else original)
pronunciation: score && [1, 2, 3].includes(score.star_band)
  ? { starBand: score.star_band as 1 | 2 | 3,
      words: wordsToPractice(score.word_scores as WordScore[], transcript) }
  : null
```
Then in `StudentMissionRecap.tsx` the "all clear" branch becomes `words.length === 0` (helper output contains only practice-eligible words), and update the source-contract assertions in `student-history-ui.test.ts` to pin `wordsToPractice` usage rather than the `label !== "Clear"` filter.

## Warnings

### WR-01: `routeAssignmentStudentToTeacherReview` mutates `needs_review_reason` before validating, and silently succeeds on lost claims leaving the attempt reopenable

**File:** `src/server/student-access/mission-flow.ts:125-171`
**Issue:** Three error-path gaps in one function: (a) `needs_review_reason` is written (line 125-128) *before* the transition is validated (line 138) and before the optimistic claim, so an `invalid_transition` failure still leaves a mutated attempt; (b) when the conditional claim loses the race (`!updated`, line 161) the function returns `{ ok: true }` without stamping the attempt out of `in_progress` and without an audit event — the exact "resume path can reopen a submitted mission" hazard the comment at line 163 says the stamping prevents; (c) the early return for `status === "completed"` (line 132) likewise leaves the attempt `in_progress` with a review reason but no status stamp.
**Fix:** Reorder: validate the transition first, perform the conditional claim, and only then write `needs_review_reason` + attempt status together. On a lost claim, re-read the row and only return `ok` if another writer actually moved it to `teacher_review`/`completed` (mirroring the `startOrResumeAttempt` lost-claim recovery).

### WR-02: `startOrResumeAttempt` lost-claim fallback returns an attempt without verifying it is resumable, with a hardcoded resume position

**File:** `src/server/student-access/mission-flow.ts:315-336`
**Issue:** When the claim update loses a race, the fallback returns `resumed.latest_attempt_id` as a resume target without checking that attempt's status (`in_progress`). If the concurrent writer completed or routed the attempt to review, the client receives a non-resumable attempt id and treats it as a live mission. It also hardcodes `resumeTurnOrder: 1` even when the concurrent attempt has finished turns, sending the student back to turn 1.
**Fix:** In the fallback, load the attempt and its turns and reuse the same resume computation as step 2 (status check + `nextUnfinishedTurnOrder`); return `not_assigned_or_started` if the latest attempt is not `in_progress`.

### WR-03: `recordHintReveal` ignores the error from the `highest_hint_level` rollup update

**File:** `src/server/student-access/mission-flow.ts:551-554`
**Issue:** The final `assignment_students` update is `await`ed but its `error` is never checked; a failed rollup silently returns `{ ok: true }`, so `highest_hint_level` can lag `attempt_turns.hint_level_used` and under-report hint usage to the teacher. (Related: the read-then-write `Math.max` pattern here is non-atomic, as the code comment acknowledges — a concurrent double-tap can regress the value.)
**Fix:**
```ts
const { error: rollupErr } = await supabase
  .from("assignment_students")
  .update({ highest_hint_level: newHighest })
  .eq("id", input.assignmentStudentId);
if (rollupErr) return { ok: false, error: "db_error" };
```

### WR-04: Recap "Completed" date renders in the server's timezone, showing the wrong day for Korean students

**File:** `src/app/student/history/[assignmentStudentId]/page.tsx:32`
**Issue:** `new Date(recap.completedAt).toLocaleDateString("en-US", { month: "long", day: "numeric" })` formats in the server's timezone (UTC on Vercel). Students are in Korea (KST = UTC+9): a mission completed at 08:59 KST on July 12 renders "Completed July 11". Every morning completion shows the previous day.
**Fix:** Pass an explicit timezone matching the audience, e.g. `toLocaleDateString("en-US", { month: "long", day: "numeric", timeZone: "Asia/Seoul" })`, or format in a client component so the browser's timezone applies.

### WR-05: Reviewed migration's `mark_submission_reviewed` is superseded by 202607120002 with materially different semantics; schema tests pin only the dead body

**File:** `supabase/migrations/202607120001_assignment_operations.sql:53-102`; `tests/schema/assignment-operations-schema.test.ts:25-33`
**Issue:** Migration `202607120002_review_any_attempt.sql` replaces `mark_submission_reviewed` entirely: the `invalid_status` rejection for non-completed/non-review states is removed (any owned latest attempt now gets a receipt). The version in the reviewed file therefore does not describe production behavior, yet `assignment-operations-schema.test.ts` asserts against 0001 only and no schema test covers 0002 (checked: `tests/schema/` has no review-any-attempt test). The suite green-lights a function body that no longer exists in the database, and the `"ok" | "not_found" | "invalid_status"` return type in `src/lib/db/types.ts:351` now includes an unreachable variant. Anyone changing 0001's function later would silently be editing dead SQL.
**Fix:** Add `tests/schema/review-any-attempt-rpc-schema.test.ts` pinning the 0002 body (receipt-only path for non-review statuses, unchanged teacher_review promotion), and add a comment in 0001 noting the function is superseded by 202607120002 (matching the pattern the 0002 header comment already uses in the other direction).

### WR-06: `request_submission_retry` nulls `latest_attempt_id`, making the retried submission invisible in every teacher queue

**File:** `supabase/migrations/202607120001_assignment_operations.sql:133-135`; consumers: `src/domain/teacher/assignment-operations.ts:9,45`, `src/server/teacher/assignment-operations.ts:79-89`
**Issue:** After a teacher requests a retry, `latest_attempt_id = null` means: (a) `listActivityForTeacher` drops the row (it filters `isLatestAttempt`, and no attempt can match a null pointer); (b) `isSubmissionPendingReview` excludes it (`isLatestAttempt` false); (c) `groupIncompleteAssignments` deliberately excludes `needs_retry` (line 45). Net effect: the assignment vanishes from Needs review, Activity, and Incomplete simultaneously. The teacher has no surface showing the retry they just requested (or its reason note) until the student starts a new attempt, and no way to confirm or reconsider the action.
**Fix:** Either keep `latest_attempt_id` pointing at the retried attempt (the `startOrResumeAttempt` needs_retry path creates a fresh attempt regardless and repoints it on claim, so nulling is not required for correctness), or make `listActivityForTeacher` include `needs_retry` rows via their most recent attempt so the action remains auditable in the UI.

## Info

### IN-01: Pronunciation block can render a bare header, and "1 turns" grammar

**File:** `src/components/student/StudentMissionRecap.tsx:7,13-19`
**Issue:** When `turn.pronunciation.words` is an empty array, both `allClear` and `practiceWords.length > 0` are false, so the IIFE returns `null` and the child sees "★★ Pronunciation" with no message beneath it. Separately, line 7 renders "1 turns" for single-turn missions.
**Fix:** Treat empty `words` as the "Great job!"/neutral case (this falls out of the CR-02 fix), and pluralize: `` `${recap.turns.length} ${recap.turns.length === 1 ? "turn" : "turns"}` ``.

### IN-02: Global inline `<style>` with `!important` hover hack in a server component

**File:** `src/app/student/history/[assignmentStudentId]/page.tsx:29`
**Issue:** The raw `<style>` tag injects a global `.recap-back-btn` class with `!important` overrides to defeat the inline style. This leaks a global class name and duplicates the pattern already solved by `student-home.css` for the home page.
**Fix:** Move the hover/active rules into a co-located CSS file (as `student-home.css` does) and drop `!important` by not setting `background` inline.

### IN-03: Due-time boundary and invalid-date handling inconsistencies in urgency grouping

**File:** `src/domain/teacher/assignment-operations.ts:46-51`; `src/domain/foundation/status.ts:103`
**Issue:** `groupIncompleteAssignments` classifies `dueTime <= now` as "missed" urgency while `shouldMarkMissed` uses strict `<`, so a row due exactly "now" displays as missed but is not marked missed. Also an unparseable `dueAt` string yields `NaN`, which silently falls through both comparisons into "later" — arguably the least urgent bucket for corrupt data.
**Fix:** Align both on strict `<` (or `<=`), and treat `Number.isNaN(dueTime)` explicitly (e.g. as `null` dueTime).

### IN-04: `ReviewEligibilityInput.attemptStatus` is loosely typed as `string`

**File:** `src/domain/teacher/assignment-operations.ts:5`
**Issue:** `status` is a strict union but `attemptStatus` is `string`, so typos like `"complete"` compile and silently return `false`.
**Fix:** Type it as `Database["public"]["Enums"]["attempt_status"]` (or a local union) to match `status`'s rigor.

### IN-05: `is_submission_review_receipt_owner` keeps default PUBLIC execute unlike sibling functions

**File:** `supabase/migrations/202607120001_assignment_operations.sql:19-35,149-152`
**Issue:** The migration revokes `mark_submission_reviewed`/`request_submission_retry` from public/anon/authenticated but leaves the SECURITY DEFINER helper `is_submission_review_receipt_owner` executable by everyone (Postgres default). Exploitability is low (`current_teacher_id()` gates it), but it breaks the migration's own hardening convention.
**Fix:** `revoke all on function public.is_submission_review_receipt_owner(uuid) from public, anon; grant execute ... to authenticated, service_role;`

### IN-06: `p_reason_note` flows unvalidated and unbounded into the audit metadata

**File:** `supabase/migrations/202607120001_assignment_operations.sql:104,143`
**Issue:** `request_submission_retry` accepts any text (null, empty, megabytes) and stores it verbatim in `assignment_status_events.metadata`. No length cap or trim exists at the SQL layer; safety depends entirely on the app-side caller.
**Fix:** Guard in the function, e.g. `values (..., jsonb_build_object('reason_note', left(coalesce(p_reason_note, ''), 500)))`.

### IN-07: Whitespace-fragile schema-test assertions

**File:** `tests/schema/assignment-operations-schema.test.ts:31`
**Issue:** `expect(sql).toContain("reason_code\n    ) values (v_assignment_student_id, 'teacher_review', 'completed'")` pins exact newline + 4-space indentation; any reformat of the SQL breaks the test without behavior change (and per WR-05 the pinned body is already superseded).
**Fix:** Assert with a whitespace-tolerant regex, e.g. `/reason_code\s*\)\s*values\s*\(v_assignment_student_id,\s*'teacher_review',\s*'completed'/`.
