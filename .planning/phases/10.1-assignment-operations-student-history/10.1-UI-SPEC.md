Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge padding, label-to-value gaps, compact metadata |
| sm | 8px | Filter gaps, compact controls, icon/text gaps |
| md | 16px | Mobile workspace padding, list/card spacing, default field spacing |
| lg | 24px | Desktop workspace and evidence-card padding |
| xl | 32px | Evidence-page outer padding and major content separation |
| 2xl | 48px | Mobile teacher-shell top offset and reserved major section break |
| 3xl | 64px | Teacher header height only |

Exceptions:

- All new or restored interactive targets must be at least **44×44px** on touch layouts. The existing recap back control is exactly 44×44px and remains unchanged.
- Existing 12px and 20px internal gaps are retained where already implemented; do not normalize them during gap closure.
- Teacher desktop sidebar width is fixed at **210px**. Student Current/Past and recap surfaces remain capped at **430px**.
- Restored review-policy control: 8px vertical/8px horizontal field padding, minimum 44px height, 210px minimum desktop width, 100% width on mobile.

## Typography

The following four-role scale governs all new or restored Phase 10.1 UI. Use exactly two weights: 400 and 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / metadata | 12px | 400 | 1.4 |
| Body / control label | 14px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.25 |
| Page display | 28px | 600 | 1.2 |

Existing queue/table micro-labels and emphasized legacy navigation text use additional shipped sizes and 700/800 weights. They are frozen for Phase 10.1 and may remain untouched; do not introduce another size or weight in the restored policy control. Phase 12 may normalize the legacy scale.

Specific restored-control typography:

- “Review setting” label: 12px/600/1.4, sentence case.
- Select value: 14px/400/1.5.
- Helper and save/error status: 12px/400/1.4.

## Surface Contracts

### Teacher workspace shell

- Desktop uses a 210px `#F8FAFC` sidebar and a single full-width white workspace. Do not return to dashboard cards or multiple competing panels.
- Sidebar order is Needs review, Incomplete, All activity, class shortcuts, Create class, Missions. Needs review and Incomplete counts are compact blue pills.
- At widths **800px and below**, hide the sidebar behind the fixed Menu trigger and reflow the workspace to one column. Menu trigger, links, and actions must have 44px touch targets.
- Shared counts refresh within 30 seconds. On `/teacher`, changed data produces the banner and rows move only after “Show now.” On other teacher routes, show the non-blocking student/assignment/class notice with View and Dismiss actions.
- Poll failures are silent and retain the last good count. Do not display a blocking page error for a transient freshness failure.

### Needs review and All activity

- Needs review is newest-first and uses full-width Gmail-like rows, not cards. Desktop columns are Student, Class (global only), Submission, Status, Received.
- Unread rows use `#EFF6FF`, a 3px inset `#2563EB` left edge, and stronger text. Opening evidence clears unread presentation but does not remove the row.
- Mark reviewed removes the row, updates the count, returns to `/teacher`, and shows Undo. Never auto-open the next item.
- All activity is durable history. “Move back to Needs review” stays inside the reviewed row overflow menu; it is not a persistent page-level action.
- On mobile, hide table headers and reflow row fields into a readable two-column stack. Preserve the same information and link target.

### Incomplete work

- Incomplete never mixes into Needs review. Order sections Missed, Due soon (within 24 hours), then collapsed Later.
- Group by assignment, showing class in the group header and one row per outstanding student-assignment item.
- Each student row shows exactly one progress pill: “Not started” or “Started.” The sidebar count is the number of student-assignment items, not assignments.
- Row activation opens assignment results with that student highlighted while nearby classmates remain visible.

### Class workspace and restored review policy

- Keep the existing class header, class code, tabs, queue, Assignments, Students, and Class settings hierarchy.
- Restore the policy control at the right side of `.class-review-header`, aligned with the class identity block. At 800px and below, it moves beneath the identity block and fills the available width.
- Use the previously shipped native `<select>` interaction, not a new settings card or modal. Options are exactly the two policy labels in the copy contract.
- The current value comes from server data. On change, disable the select and announce the pending status in a `role="status"`/`aria-live="polite"` region without moving focus.
- After success, refresh class queue and shared counts, retain focus on the select, and announce “Review setting updated.” The class subtitle must reflect the selected policy.
- On failure, return the select to the last server-confirmed value, retain the existing queue/counts, and show the error in `role="alert"`. Never leave a choice visually selected if it was not persisted.
- Switching to flagged-only immediately removes ordinary unreviewed completions from Needs review after the successful refresh; those rows remain in All activity. Switching back may reveal still-unreviewed ordinary completions. Neither choice changes student completion status.
- No confirmation modal is required because the setting is reversible and does not mutate homework completion. The explanatory helper text must make the queue consequence clear before selection.

### Teacher evidence

- Evidence remains transcript-first. Audio and pronunciation diagnostics stay additive and never displace transcripts.
- Ordinary completed evidence exposes exactly two primary actions: Mark reviewed and Request retry. Do not add a third follow-up state.
- Request retry keeps the existing modal and optional note. Mark reviewed does not need a modal because Undo and permanent reopen exist.
- Incomplete evidence may show Mark as done plus Request retry. Mark as done remains reversible and returns to the filtered incomplete list.
- Action errors are inline below controls, use `role="alert"`, and never erase the evidence already on screen.

### Student Current and Past missions

- Student home remains a phone-oriented surface capped at 430px. On screens at or below 430px it becomes full-viewport with no outer radius or shadow.
- Tabs are exactly Current and Past missions. Current orders Retry, due soon, then later/no date. Waiting-for-review remains Current. Past contains only completed missions, newest first, five per page.
- Mission cards remain 12px-radius white cards with a status pill and one obvious full-width action. Late/missed open work remains launchable.
- Empty states and pagination copy are fixed by the copy contract. Preserve “Up to 5 missions per page.”

### Read-only recap

- Open only the unlocked student’s latest completed attempt. Display one reconstructed conversation sequence: Coco prompt, “You said” transcript, available recording, and qualitative pronunciation feedback.
- Coco bubble is white with a neutral border; student bubble is `#DBEAFE`; pronunciation feedback is positive green. Never show raw numeric pronunciation scores.
- Retained audio is loaded on demand. Expired audio shows “Recording expired”; unavailable non-retention failures show “Recording unavailable.” Transcript and feedback remain visible in both states.
- The arrow-only “Back to past missions” control remains a 44×44px solid-blue button with the accessible label and title “Back to past missions.”
- No edit, resume, re-record, retry, or resubmit control appears anywhere in history.

## Verification-Gap Interaction States

### Gap 1 — per-class review policy

The restored UI must cover these observable states:

| State | Visual/interaction contract |
|-------|-----------------------------|
| Initial | Select shows server-confirmed policy; matching helper text is visible |
| Saving | Select disabled; “Saving review setting…” announced; queue does not optimistically disappear |
| Success | Select enabled; queue/count refresh once; class subtitle changes; success announced; focus remains on select |
| Failure | Prior choice restored; queue/count unchanged; inline alert shown; retry is possible by selecting again |
| Flagged-only result | Ordinary completions absent from Needs review but present in All activity; flagged rows remain |
| Every-submission result | Ordinary and flagged eligible completions appear in Needs review if not reviewed |

### Gap 2 — protect late-opened in-progress attempts

This is a server/domain fix with no new control, banner, toast, or confirmation. The UI-visible invariant is:

- Once a late/missed mission is opened and has an in-progress attempt, its Current card and teacher incomplete row continue to show the in-progress/“Started” state across the missed-status job.
- Reopening the mission resumes the same attempt and preserved turns; it must not flash back to “Missed,” create a new empty attempt, or display a false reset message.
- The fix must not alter the existing launch action, card layout, queue ordering, or copy.

## Accessibility and Responsive Contract

- Every interactive control has a visible `:focus-visible` ring with at least 3:1 contrast and a 44px touch target on mobile.
- Native select has a programmatic label; pending/success uses polite live status; failure uses `role="alert"`.
- Color is never the only indicator: unread has bold text/edge, status pills contain text, active tabs use `aria-current`, mobile menu uses `aria-expanded`, and selected incomplete student uses `aria-current` plus visible highlight.
- Queue row links retain a logical tab order. Overflow menu summary is named “Submission actions.” Dismiss buttons have accessible names.
- New-submissions banner never steals focus. After activation and refresh, focus returns to the banner’s logical location or the Needs review heading; it must not jump to the first row.
- Respect `prefers-reduced-motion`; retain the existing near-zero transitions and disable decorative movement.
- At 800px and below, class policy, class cards, queue rows, and activity rows reflow without horizontal scrolling. At 430px and below, student surfaces are full-viewport.
