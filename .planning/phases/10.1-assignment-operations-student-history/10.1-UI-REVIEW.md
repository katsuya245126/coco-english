# Phase 10.1 — UI Review

**Audited:** 2026-07-14
**Baseline:** `10.1-UI-SPEC.md` (approved design contract) and `10.1-CONTEXT.md`
**Screenshots:** Not captured (no dev server on ports 3000, 5173, or 8080; code-only audit)
**Blockers:** None. No pillar scored 1/4 and no task-blocking defect was found.

---

## Pillar Scores

| Pillar | Score | Key Finding |
|--------|-------|-------------|
| 1. Copywriting | 3/4 | Most fixed workflow copy matches, but the retry cancel label and new-submission count diverge from the contract. |
| 2. Visuals | 3/4 | Queue, class-policy, student-card, and recap structures are clear, but the recap title lacks a defined display style and mobile control hierarchy is uneven. |
| 3. Color | 3/4 | The 60/30/10 white-neutral-blue direction is substantially preserved, with a few undeclared blue/lavender shades outside the approved palette. |
| 4. Typography | 2/4 | The restored policy control is exact, but the recap display title is unstyled and the shipped operational surfaces use a very fragmented type scale. |
| 5. Spacing | 2/4 | Desktop spacing is coherent, but several mobile targets are below 44px and the recap does not adopt the required full-viewport mobile treatment. |
| 6. Experience Design | 2/4 | Core success paths exist, but loading/error/empty coverage is incomplete and several async failures are silent or can strand controls. |

**Overall: 15/24**

---

## Top 3 Priority Fixes

1. **Bring mobile targets and recap layout up to contract** — undersized student pagination/tabs, teacher navigation controls, and the fixed-padding recap make touch use harder — enforce 44px minimum targets at `max-width: 800px`, add focus-visible treatment, and make the recap full-viewport at 430px and below.
2. **Restore recap display hierarchy** — the recap title has no Phase 10.1 typography style and can inherit Tailwind's reset size/weight — apply the declared 28px/600/1.2 display role and preserve a clear heading-to-metadata-to-conversation hierarchy.
3. **Complete resilient interaction states** — failed activity reopen/Undo actions are silent, history audio can remain pending after a thrown action, and Incomplete has no true empty state — add inline/live errors, `try/catch/finally` recovery, and a useful empty state without removing existing content.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- **WARNING — Retry confirmation uses the wrong escape label.** The approved confirmation specifies “Keep submission,” but the dialog renders “Cancel” (`src/components/teacher/SubmissionReviewControls.tsx:93-100`). This is understandable but less explicit about what remains unchanged.
- **WARNING — The inbox banner labels the total queue as new submissions.** `pendingInboxSnapshot.needsReviewCount` is rendered as “{count} new submissions” (`src/components/teacher/TeacherWorkspaceShell.tsx:47-51,84`). That value is the total Needs review count, not the number newly arrived, and the string also produces “1 new submissions.” Compute the delta/new-row count or use copy that truthfully describes the total.
- **PASS — Binding workflow and empty-state strings are otherwise present.** “Mark reviewed,” “Request retry,” “Submission marked reviewed,” “Move back to Needs review,” the Needs review and All activity empty states, both student empty states, “Recording expired,” and the read-only recap notice match the contract (`src/components/teacher/TeacherQueueViews.tsx:28-60`; `src/components/student/StudentHomeShell.tsx:27-37`; `src/components/student/StudentMissionRecap.tsx:11-19`).
- **PASS — Plan 08/12 gap copy is preserved.** The recap renders “Pronunciation,” “Great job!,” and “Words to practice:” from the server-filtered practice list (`src/components/student/StudentMissionRecap.tsx:13-17`).

### Pillar 2: Visuals (3/4)

- **PASS — The primary teacher surface retains the intended Gmail-like hierarchy.** A fixed 210px sidebar feeds one workspace; queue headers and full-width rows distinguish student, class, submission, status, and time, with unread rows receiving background, edge, and stronger text (`src/app/teacher/teacher-workspace.css:1-28,98-116`; `src/components/teacher/TeacherQueueViews.tsx:28-36`).
- **PASS — Plan 10's policy control is visually subordinate and well placed.** It remains a native control aligned in `.class-review-header`, uses a 210px desktop width, and reflows to full width at 800px (`src/app/teacher/classes/[id]/(workspace)/layout.tsx:15-25`; `src/app/teacher/teacher-workspace.css:38-52,81-90`).
- **WARNING — The recap title has no explicit visual role.** The `<h1>` only sets `marginBottom` (`src/app/student/history/[assignmentStudentId]/page.tsx:31`), while Tailwind preflight resets headings to inherit. It can therefore render with insufficient distinction from completion metadata and conversation content. Apply the contract's page-display style.
- **WARNING — Several important mobile controls lack an adequately strong control silhouette.** Teacher sidebar links, filters, class tabs, the Menu trigger, and student tabs rely mainly on text padding/underlines rather than the specified 44px touch geometry (`src/app/teacher/teacher-workspace.css:5,53-57,83-90,104-105`; `src/app/student/home/student-home.css:12-15`). The visual affordance is clearest on mission actions and the recap back button, but inconsistent across navigation.

### Pillar 3: Color (3/4)

- **PASS — The dominant palette follows the contract.** White workspace/cards, `#F8FAFC` neutral surfaces, `#EFF6FF` unread/selected surfaces, and `#2563EB` actions/links/counts are consistently used. The primary blue appears on contract-reserved elements rather than indiscriminately filling cards (`src/app/teacher/teacher-workspace.css`; `src/app/student/home/student-home.css`).
- **PASS — Semantic statuses remain text-backed and color is not the sole signal.** Retry/late, started/due-soon, completed, and waiting-for-review use the specified red, amber, green, and purple families with visible labels (`src/app/student/home/student-home.css:27-32`; `src/app/teacher/teacher-workspace.css:112-129`).
- **WARNING — A few surfaces introduce undeclared palette variants.** The recap scene uses `#EEF2FF`, student progress uses `#60A5FA`, and class accents use `#E0E7FF/#3730A3` (`src/components/student/StudentMissionRecap.tsx:22`; `src/app/student/home/student-home.css:29-30`; `src/app/teacher/teacher-workspace.css:63,73`). They are visually related, but they weaken the approved `#FFFFFF` / `#F8FAFC` / `#EFF6FF` / `#2563EB` distribution. Keep these only if explicitly grandfathered; otherwise map them to declared secondary/semantic tokens.
- **Registry audit:** `components.json` is present, but the UI spec declares no third-party registries and no installed block. Zero third-party blocks required checking; no registry flags.

### Pillar 4: Typography (2/4)

- **PASS — Plan 10's restored control exactly matches its type contract.** Label is 12px/600/1.4, select is 14px/400/1.5, and helper/status/error text is 12px/400/1.4 (`src/app/teacher/teacher-workspace.css:44-52`).
- **WARNING — The recap page display heading is not assigned the required 28px/600/1.2 role.** The title has only a margin override (`src/app/student/history/[assignmentStudentId]/page.tsx:31`). Import and apply `displayTitleStyle` or an equivalent local style.
- **WARNING — The operational surfaces contain a fragmented legacy scale.** The audited CSS uses 10, 11, 12, 13, 14, 15, 18, 19, 21, 22, 25, 27, and 28px plus 700/800 weights (`src/app/teacher/teacher-workspace.css`; `src/app/student/home/student-home.css`). The spec freezes some queue micro-labels and emphasized legacy navigation, so wholesale normalization is out of scope, but new edits should not extend this scale and Phase 12 should consolidate it.
- **WARNING — Child-facing metadata is frequently 10–11px.** Status badges, due/completion metadata, pagination, and page hints use 10–11px (`src/app/student/home/student-home.css:26-39`), below the contract's 12px caption role. These shipped values may be grandfathered, but they reduce legibility for elementary learners.

### Pillar 5: Spacing (2/4)

- **PASS — Major desktop dimensions match.** Sidebar is 210px, header is 64px, workspace/evidence padding uses 24/32px, student home is capped at 430px, and the review-policy select is at least 44px (`src/app/teacher/teacher-workspace.css:1,23,26,44-47`; `src/app/student/home/student-home.css:4-7`).
- **WARNING — Multiple interactive targets are below the required 44×44px touch size.** Student pager controls are 30×30 and Switch class is 42px high (`src/app/student/home/student-home.css:36-40`). Teacher mobile Menu, sidebar links, filters, class tabs, pagination links, notice dismissal, activity overflow summary, and Undo do not establish a 44px minimum (`src/app/teacher/teacher-workspace.css:5,31-36,53-57,83-90,104-105,118-120,134-135`).
- **WARNING — The recap is not full-viewport at 430px and below.** It always uses `pageStyle`'s 24px padding and `panelStyle`'s border/radius (`src/components/student/styles.ts:6-24`; `src/app/student/history/[assignmentStudentId]/page.tsx:28-34`). Unlike student home, it has no mobile media rule to remove outer chrome, contrary to the student-surface responsive contract.
- **WARNING — Some spacing values fall outside the declared scale without being listed exceptions.** Examples include 9px, 10px, 13px, 14px, 15px, 18px, 22px, and 34px throughout the queue/student CSS (`src/app/teacher/teacher-workspace.css:3-8,28-29,53-74,102-135`; `src/app/student/home/student-home.css:7-40`). Existing 12/20px gaps are explicitly grandfathered, but these additional values should be treated as legacy debt rather than a compliant spacing system.

### Pillar 6: Experience Design (2/4)

- **PASS — Core interaction contracts are implemented.** The policy select covers initial, disabled saving, success, rollback error, live-region announcement, success-only refresh, and focus restoration (`src/components/teacher/ClassReviewPolicyControl.tsx:27-90`). Evidence keeps the exact primary review/retry actions, inline error, confirmation, and redirect behavior (`src/components/teacher/SubmissionReviewControls.tsx:36-103`). Current/Past separation, bounded pagination, launchability, and read-only recap behavior are present (`src/components/student/StudentHomeShell.tsx`; `src/components/student/AssignmentListItem.tsx`; `src/components/student/StudentMissionRecap.tsx`).
- **WARNING — Activity recovery failures are silent.** “Move back to Needs review” and Undo ignore unsuccessful results and expose no `role="alert"` feedback (`src/components/teacher/TeacherQueueViews.tsx:48-56`). A teacher can click a recovery action and receive no explanation or retry guidance.
- **WARNING — History audio can become permanently pending after a thrown action.** `loadHistoryAudioAction` is awaited without `try/catch/finally`; an exception skips `setPending(false)` (`src/components/student/StudentHistoryAudioPlayer.tsx:9-16`). Keep transcript visible, recover the button, and announce “Recording unavailable.”
- **WARNING — Incomplete has no true empty state.** With no groups, the page still renders empty Missed/Due soon headings and a Later disclosure rather than a concise completion message (`src/components/teacher/TeacherQueueViews.tsx:39-46`).
- **WARNING — Route-level loading/error coverage is absent on the audited teacher and student-history surfaces.** There are no colocated `loading.tsx` or `error.tsx` files. Server navigation therefore lacks phase-specific pending/error presentation, despite several data-heavy queue/evidence/history routes.
- **WARNING — Filter and refresh focus behavior is incomplete.** Queue filters do not expose selected state via `aria-current`, and the new-submissions banner is removed immediately before `router.refresh()` without explicit focus restoration to the heading/logical location (`src/components/teacher/TeacherQueueViews.tsx:20-21`; `src/components/teacher/TeacherWorkspaceShell.tsx:64,84`).
- **WARNING — Several icon-only or compact controls lack contract-complete focus treatment.** The recap back link has hover/active rules but no visible `:focus-visible` rule, and the student history audio button is inline-styled without one (`src/app/student/history/[assignmentStudentId]/page.tsx:8-30`; `src/components/student/StudentHistoryAudioPlayer.tsx:15-16`).
