<objective>
Relax the snapshot-turn gate only for legitimate dynamic chat turns and thread honest nullable evaluator grounding through the live upload pipeline.

Purpose: Chat missions already permit fewer authored templates than required turns, but the upload path currently rejects every turn beyond that array. This plan makes those turns runnable without weakening ownership, hard-cap, preset, pronunciation, or audit guarantees.
Output: Nullable evaluator support, one reordered persisted-line lookup, a cap-preserving dynamic gate, and focused chat/preset regressions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| student client -> service-role audio pipeline | Untrusted assignment/attempt/turn identifiers and audio metadata enter an ownership-sensitive server module |
| persisted attempt_turns -> evaluator | A prior moderated Coco line is reused as semantic grounding for the next child response |
| transcript/context -> OpenAI evaluator | Student transcript and bounded mission context cross to a third-party model |

| T-11.1-12 | Tampering | forged turnOrder | mitigate | Missing snapshot allowed only through server-owned `canGenerateNextDynamicTurn`; turn above HARD_TURN_CAP fails before upload/evaluation/generation |
