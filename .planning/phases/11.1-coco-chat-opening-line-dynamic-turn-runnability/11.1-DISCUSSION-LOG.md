## Opening-Line Source (advisor-researched)

| Option | Description | Selected |
|--------|-------------|----------|
| Save-time + editable | Generate opener at mission-save into teacher-editable field (D-07 pattern), store as turn-1 template row, validation backstop | ✓ |
| Runtime generator | Transcript-optional generator at attempt start; per-student variety but latency/moderation/unreviewed-copy costs and no snapshot-gate fix | |
| Require 1 authored turn | Validation-only interim; reverses shipped 11-05 zero-turn UI | |

**User's choice:** Save-time + editable (recommended)
**Notes:** Researcher highlighted that storing the opener as a turn-1 template clears the audio-upload snapshot gate for turn 1 without touching that code, and gives every dynamic turn N≥2 a real previousCocoLine.

## Dynamic-Turn Snapshot Dependency (advisor-researched)

| Option | Description | Selected |
|--------|-------------|----------|
| Nullable threading | Chat-aware gate reusing existing cap check; missionQuestion = persisted coco_line; evaluator accepts targetExample: null; skip exact-match fast path; no schema change | ✓ |
| Virtual snapshot turn | Fabricate a template server-side; single insertion point but biases evaluator's improved_sentence and fakes hint provenance | |
| Materialize attempt rows | New additive columns per dynamic turn; strongest provenance but migration + write-ordering risk, duplicates coco_line persistence | |

**User's choice:** Nullable threading (recommended)
**Notes:** Research found the dependency fan-out smaller than feared: pronunciation scoring never needs targetExample on dynamic turns (originals→transcript, repeats→improved_sentence); the evaluator is the only real consumer.
