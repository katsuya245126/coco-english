<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teacher session -> generate action | Only an authenticated teacher may submit scene/pattern input to the paid adapter |
| teacher-authored input -> OpenAI | Teacher text crosses to a third-party model as bounded prompt data |
| model output -> teacher form | Untrusted provider output remains an unsaved draft until schema validation and teacher review |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-01 | Spoofing | `generateOpenerAction` | mitigate | Call `requireTeacherProfile()` before input validation or provider work; source contract guards ordering |
| T-11.1-02 | Tampering | opener structured output | mitigate | Parse with bounded Zod schema; malformed/oversized values fail closed to a soft error |
| T-11.1-03 | Information Disclosure | provider prompt | mitigate | Send only scene premise and target pattern; prompt forbids names, PINs, audio keys, or private class data |
| T-11.1-04 | Information Disclosure | child-facing opener safety | accept | D-05 intentionally treats the opener as teacher content: generate action never persists/exposes it, and the authenticated teacher reviews/edits it before the normal save path |
| T-11.1-05 | Denial of Service | provider failure | mitigate | Typed failure maps to retry-in-form/manual-entry soft error; no save occurs until D-03 validation later passes |
| T-11.1-SC | Tampering | npm/pip/cargo installs | mitigate | No install task and no new package; existing OpenAI/Zod dependencies only |
</threat_model>
