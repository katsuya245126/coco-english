<objective>
Deliver the teacher class-management vertical slice: a logged-in teacher creates a class, sees it in their dashboard list with roster count and join code, edits and archives classes, and shares the class via a join code, link, and QR code — with a teacher-only join-code reset that affects new entry only (D-18). All reads/writes go through the RLS-bound SSR user client so a teacher only ever touches their own classes.

This slice builds directly on the auth + RLS foundation from plan 02-01. After this plan a real teacher can create and manage classes and produce a shareable join code/QR — the entry point students will use in plan 02-04.

Purpose: CLASS-01, CLASS-04, and the class-side of AUTH-04 (D-03, D-09, D-18, D-15).
Output: join-code generator, class service (create/edit/archive/reset/list), class list + form + share dialog UI, class actions, join-code unit tests, and class-management e2e.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teacher browser -> class server actions | Untrusted class name / class id input crosses here |
| Next.js server (user client) -> Postgres RLS | Class read/write scoped to owning teacher via auth.uid() |
| class join code -> public student entry | Join code is a low-secrecy classroom locator shared widely |
| npm registry -> build | qrcode dependency supply chain |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Elevation of Privilege (IDOR) | /teacher/classes/[id] and class actions | mitigate | All class reads/writes use the RLS-bound SSR client + requireTeacherProfile; a teacher cannot load or mutate another teacher's class id |
| T-02-07 | Tampering / Information Disclosure | join code guessing | accept (low) | Join code is intentionally low-secrecy (classroom sharing); the real access gate is the per-student PIN (plan 04); codes use a non-ambiguous alphabet and are resettable |
| T-02-08 | Denial of Service | join-code uniqueness collisions | mitigate | DB unique constraint + regenerate-and-retry in createClass/resetJoinCode |
| T-02-SC | Tampering | npm install qrcode | mitigate | Blocking human-verify checkpoint (Task gate) before install per 02-RESEARCH Package Legitimacy Audit; [ASSUMED]/[SUS] cannot be auto-approved |
