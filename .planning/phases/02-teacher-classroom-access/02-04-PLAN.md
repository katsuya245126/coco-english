<objective>
Deliver the student-access vertical slice: a student opens a class by QR/link or typed class code, the device remembers the class context (but never the unlock), the student types their name and a 4-digit PIN, and on a correct tuple lands on a no-homework student home shell. Every failure — wrong code, wrong name, wrong PIN — returns the identical generic mismatch message (D-16). This plan also closes AUTH-04 by adding an automated cross-teacher RLS isolation test across classes, students, and linked rows.

This slice consumes plan 02-02's join codes and plan 02-03's students/PINs. After this plan a real student can go from a shared link to their homework shell without any account, and we have proof that teachers are isolated from each other's data.

Purpose: STUD-01, STUD-02, STUD-03, STUD-04, STUD-05, and final AUTH-04 verification (D-10, D-11, D-12, D-13, D-14, D-16, D-17, D-18, D-15).
Output: student-access schemas, class lookup + unlock services, join/name/PIN routes + actions, remembered-class banner, student home shell, and server + e2e tests including cross-teacher isolation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| student browser (unauthenticated) -> join/unlock server action | Fully untrusted input: join code, typed name, PIN |
| unlock server action -> Postgres (service-role client) | Student access has no Supabase Auth session; verification is app-owned and server-only |
| student device localStorage -> class context | Low-trust remembered class id/code; never a homework unlock |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Spoofing | online PIN brute force (10,000-value space) | mitigate | Server-only verifyPin with generic errors; reserve per-class/student/IP throttling hooks; failed-unlock attempts are server-side only and reveal nothing; PIN is resettable by the teacher |
| T-02-14 | Information Disclosure | roster/name/code enumeration via error text | mitigate | Single generic_mismatch result for wrong code, wrong name, and wrong PIN (D-16); no visible roster selector (D-11); class context shown only after safe join-code resolution |
| T-02-15 | Elevation of Privilege | service-role client used for student access | mitigate | Service-role client confined to server-only student-access modules; never imported into a client component; only minimal class/student context returned to the browser |
| T-02-16 | Denial of Service / Availability | join-code reset stranding remembered devices | mitigate | Remembered class id/context stored separately from the live join code so a reset affects new entry only (D-18) |
| T-02-17 | Elevation of Privilege (cross-tenant) | teacher A reading teacher B's rows | mitigate | Automated cross-teacher isolation test across classes, students, and linked rows (Task 3) closes AUTH-04 |
| T-02-SC | Tampering | npm installs | n/a | No new packages installed in this plan |
</threat_model>
