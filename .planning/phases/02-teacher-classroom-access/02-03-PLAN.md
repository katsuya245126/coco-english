<objective>
Deliver the roster-and-PIN vertical slice: a teacher opens a class, bulk-pastes student names (with blanks and duplicates surfaced), edits and archives individual students, and generates/resets each student's auto-generated 4-digit PIN — with only a salted+peppered hash stored and the cleartext PIN shown exactly once. All operations run through the RLS-bound SSR client so a teacher only touches their own roster.

This slice builds on plan 02-01's auth/RLS foundation and complements plan 02-02's class management. After this plan a real teacher can populate a class roster and hand each student a PIN — the credentials students will use to unlock homework in plan 02-04.

Purpose: CLASS-02, CLASS-03, and the roster side of AUTH-04 (D-05, D-06, D-07, D-08, D-15).
Output: pure PIN helpers, roster parser, roster service, the class roster-management detail page + actions, roster editor / paste form / PIN action UI, and unit + e2e tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teacher browser -> roster server actions | Untrusted pasted names / student ids / PIN-reset requests cross here |
| Next.js server (user client) -> Postgres RLS | Roster read/write scoped to the owning teacher via auth.uid() |
| server -> students.pin_hash | PIN secret material; only a salted+peppered hash is persisted |
| PIN_HASH_PEPPER env -> runtime | Server-only secret that must never reach the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Information Disclosure | students.pin_hash storage | mitigate | Store only a salted + peppered hash via Node crypto; never persist plaintext; cleartext returned once at generation, never re-read; pepper is a server-only env var |
| T-02-10 | Elevation of Privilege (IDOR) | roster page + roster actions | mitigate | RLS-bound SSR client + requireTeacherProfile; a teacher cannot load or mutate another teacher's roster |
| T-02-11 | Tampering | pepper leakage to client bundle | mitigate | PIN_HASH_PEPPER read only in server modules; acceptance criterion greps that no client component references it |
| T-02-12 | Information Disclosure | duplicate-name leakage during paste | accept (low) | Duplicate/blank surfacing is to the owning teacher only (already authorized); no cross-tenant exposure |
| T-02-SC | Tampering | npm installs | n/a | No new packages installed in this plan (Node built-in crypto only) |
</threat_model>
