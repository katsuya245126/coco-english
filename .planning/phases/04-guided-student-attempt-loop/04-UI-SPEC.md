# Phase 04 — UI Design Contract

> Visual and interaction contract for Phase 4 frontend work. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Continues the Phase 2/3 design system with no changes to tokens, colors, typography, or spacing. Phase 4 is entirely student-facing and mobile-first.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none; continue building local React components with inline `React.CSSProperties` objects, consistent with Phases 2-3 |
| Icon library | text labels for all actions; no icon library required for Phase 4 student flow |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hint tier indicator gaps, progress indicator inner spacing, badge padding |
| sm | 8px | Turn counter margin, buddy line spacing, hint tier vertical gaps |
| md | 16px | Assignment list row padding, step card inner section spacing, input-to-button gap |
| lg | 24px | Step card padding, assignment list section padding, page horizontal padding |
| xl | 32px | Vertical gap between step cards and progress indicator, major section breaks |
| 2xl | 48px | Top spacing above step cards on mission flow, empty state vertical centering |
| 3xl | 64px | Maximum page-level top/bottom spacing |

Exceptions: All interactive controls (buttons, text inputs) must be at least 44px tall for mobile touch targets (carried from Phase 2). Hint reveal buttons use 44px minimum height despite being secondary actions.

| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.25 |

## Phase 4 Screen Contracts

### Assignment List (Student Home Shell Extension)

The existing `StudentHomeShell` is extended from its Phase 2 "no homework" state to display the student's assignment list. The shell continues to use the student page layout: `#F7F8FA` background, centered content, max-width 420px, 24px horizontal padding.

**Layout:**
1. Class name (Display, `#111827`)
2. Signed-in-as line: "Signed in as **{displayName}**" (Body, `#4B5563`, 24px bottom margin)
3. Section heading: "Your homework" (Heading, `#111827`, 8px bottom margin)
4. Assignment list items OR empty state

**Assignment list item:**
Each item is a white card (`#FFFFFF`, 1px `#D1D5DB` border, 8px radius, 16px padding) with 8px vertical gap between items.

Contents per item:
- Row 1: Assignment title (Body, 16px, weight 400, `#111827`, truncate with ellipsis if longer than one line) and status badge (right-aligned)
- Row 2: Turn count "{N} turns" (Label, 14px, `#4B5563`) and due date "Due {date}" or "No deadline" (Label, 14px, `#4B5563`, right-aligned)

**Status badges:**

| Status | Label | Background | Text Color | Border |
|--------|-------|------------|------------|--------|
| assigned | Start | `#2563EB` | `#FFFFFF` | none |
| started | Continue | `#FFFFFF` | `#2563EB` | 1px `#2563EB` |
| completed | Done | `#F0FDF4` | `#177245` | 1px `#BBF7D0` |
| closed/expired | Closed | `#F7F8FA` | `#6B7280` | 1px `#E5E7EB` |

Badge styling: 14px, weight 600, 4px vertical padding, 12px horizontal padding, 9999px border-radius (pill shape). The "Start" and "Continue" badges are tappable and navigate to the mission flow. The "Done" and "Closed" badges are non-interactive.

**Empty state:** When the student has no assignments at all, show the existing Phase 2 empty state: Heading "No homework yet", Body "You are signed in for this class. Your teacher has not assigned speaking homework yet." in the centered card layout.

**Closed/expired items:** Items whose `due_at` has passed are displayed with the "Closed" badge. They are not tappable. The closed/expired explanation copy "This homework is not open right now. Ask your teacher what to do next." is shown inline below the item metadata when the item has a past `due_at`.

**Switch class action:** The "Switch class" secondary button remains at the bottom, below the assignment list.

### Mission Flow (Per-Turn Step Cards)

The mission flow is a single mobile-first route (within the student route tree, gated by the unlock cookie). It follows the "one focused screen per step" pattern from CONTEXT.md D-12.

**Page layout:** `#F7F8FA` background, centered content, max-width 420px, 24px horizontal padding, 48px top padding.

**Page header:**
- Mission title (Display, `#111827`, 8px bottom margin)
- Turn progress indicator: "Turn {current} of {total}" (Label, 14px, weight 600, `#4B5563`)
- Progress bar: a horizontal bar below the turn indicator, full width, 4px height, `#E5E7EB` background, `#2563EB` filled portion representing completed turns as a fraction of total turns. 9999px border-radius.

**Step card:** Each step is a white card (`#FFFFFF`, 1px `#D1D5DB` border, 8px radius, 24px padding) displayed below the progress bar with 24px top margin. Only ONE step card is visible at a time (D-12). Steps within a turn transition by replacing the card content, not by scrolling.

#### Step 1: Buddy Question + Student Answer

The card contains:

1. **Buddy speech area:** A card-within-card with `#EFF6FF` background, 1px `#BFDBFE` border, 8px radius, 16px padding.
   - "Coco asks:" (Label, 14px, weight 600, `#4B5563`, 4px bottom margin)
   - The buddy question from the snapshot turn prompt (Heading, 20px, weight 600, `#111827`)

2. **Hint area** (below buddy speech, 16px top margin): Initially collapsed. A secondary-style text button "Need a hint?" (14px, weight 600, `#2563EB`, no background, no border, 44px min height). Tapping reveals hint tiers one at a time in order (D-07):
   - Each revealed tier is a small block: tier label (Label, 14px, weight 600, `#4B5563`) on its own line, hint content (Body, 16px, weight 400, `#111827`) below it. Tiers separated by 8px vertical gap.
   - After revealing tier 1, the button text changes to "More hints". After revealing tier 2, button changes to "More hints" still (reveals tier 3 on next tap). After all 3 revealed, button text is "All hints shown" and becomes disabled (`#6B7280`, no pointer cursor).
   - Hint background: `#FFFFFF` with 1px `#E5E7EB` border, 8px radius, 12px padding. Sits inside the main step card.

3. **Answer input area** (below hint area, 16px top margin):
   - Label "Your answer" (Label, 14px, weight 600, `#111827`, 8px bottom margin)
   - Text input (full width, 44px min height, 16px font, 1px `#D1D5DB` border, 6px radius, `10px 12px` padding)
   - Validation error "Type an answer before submitting." (14px, `#B42318`, 8px top margin, hidden unless empty submit attempted)

4. **Submit button** (below input, 16px top margin):
   - "Submit answer" (primary button: full width, 44px min height, `#2563EB` background, `#FFFFFF` text, 16px, weight 600, 6px radius)

#### Step 2: Improved Sentence + Required Repeat

After submitting a non-empty answer, the card transitions to show:

1. **Student's original answer** (read-only display):
   - "Your answer:" (Label, 14px, weight 600, `#4B5563`, 4px bottom margin)
   - The submitted answer text (Body, 16px, weight 400, `#111827`)

2. **Improved sentence area** (16px top margin): A card-within-card with `#F0FDF4` background, 1px `#BBF7D0` border, 8px radius, 16px padding.
   - "Nice! Here is a better way to say it:" (Label, 14px, weight 600, `#4B5563`, 4px bottom margin)
   - The improved target-form sentence from the snapshot (Heading, 20px, weight 600, `#111827`)

3. **Repeat instruction** (16px top margin):
   - "Now try saying it this way:" (Body, 16px, weight 400, `#4B5563`, 8px bottom margin)

4. **Repeat input area:**
   - Label "Your repeat" (Label, 14px, weight 600, `#111827`, 8px bottom margin)
   - Text input (same styling as answer input)
   - Validation error "Type the sentence before submitting." (14px, `#B42318`, 8px top margin, hidden unless empty submit attempted)

5. **Submit button:**
   - "Submit repeat" (primary button, same styling as submit answer)

#### Step 3: Turn Transition (between turns)

After submitting a non-empty repeat, if more turns remain:

1. **Success message:**
   - "Good job! Ready for the next one." (Body, 16px, weight 400, `#177245`, centered text)

2. **Next turn button** (16px top margin):
   - "Next turn" (primary button, full width)

Tapping "Next turn" advances the turn counter, updates the progress bar, and transitions back to Step 1 with the next turn's buddy question.

#### Step 4: Mission Completion

After submitting the repeat on the final turn:

1. **Completion heading:** "Mission complete!" (Display, 28px, weight 600, `#111827`, centered)
2. **Completion body:** "Great work! You finished all {N} turns. Your teacher will see your answers." (Body, 16px, weight 400, `#4B5563`, centered, 8px top margin)
3. **Completion CTA** (24px top margin):
   - "Back to homework" (primary button, full width, navigates back to the assignment list)

### Resume Behavior

When a student returns to an in-progress mission (D-04), the flow:
- Opens at the next unfinished turn (not turn 1)
- Shows a brief notice at the top of the step card: "Welcome back! Picking up where you left off." (Body, 16px, weight 400, `#4B5563`, 12px padding, `#F7F8FA` background, 1px `#E5E7EB` border, 8px radius, 16px bottom margin). This notice disappears after the student submits their first answer in the resumed session or after 5 seconds, whichever comes first.

## Interaction States

| Component | Required States |
|-----------|-----------------|
| Primary buttons (Submit answer, Submit repeat, Next turn, Start mission, Finish mission) | default, hover, focus-visible, disabled (while submitting), loading (text changes to "Submitting..." with button disabled) |
| Text inputs (answer, repeat) | default, focus-visible, invalid (red border `#B42318` + error text), disabled (while submitting) |
| Assignment list items (Start/Continue) | default, hover (subtle background shift to `#F7F8FA`), focus-visible, tapped/active |
| Assignment list items (Done/Closed) | static display only, no hover/active states |
| Status badges | static display; Start and Continue badges inherit their parent item's interactive states |
| Hint reveal button | default, hover, focus-visible, disabled (all hints shown) |
| Hint tiers | hidden, revealed (animate in with a simple fade, 150ms) |
| Progress bar | updates fill width on turn completion |
| Step card transitions | crossfade or instant replacement (no slide animation required; keep it simple) |
| Resume notice | visible on entry, auto-dismisses after 5 seconds or first interaction |
| Mission completion screen | static display, back-to-homework button |

Focus rings use `#2563EB` at 2px with 2px offset (consistent with Phase 2/3, set globally in root layout). All interactive elements are keyboard-accessible. Tab order within a step card follows visual order: hint button, input, submit button.

## Layout And Responsiveness

Phase 4 is entirely student-facing and mobile-first. There are no teacher-facing screens in this phase.

Student layout:
- Background: `#F7F8FA`, full viewport height minimum
- Content: centered, max-width 420px, 24px horizontal padding
- All elements stack vertically in a single column at all screen sizes
- Text inputs and buttons are always full-width within the content area

| Range | Contract |
|-------|----------|
| `<420px` | Full-width content with 24px horizontal padding; all elements stacked; input kept above virtual keyboard by browser default scroll-into-view |
| `420px-768px` | Centered 420px content area; same stacked layout |
| `>768px` | Centered 420px content area; no change in layout (students may use tablets in landscape but the flow stays narrow and focused) |

The active input must remain visible above the on-screen keyboard (D-12). Do not use `position: fixed` for the submit button; let the browser's native scroll-into-view behavior keep the focused input visible. If native behavior is insufficient on tested devices, add a small `scrollIntoView({ block: 'center' })` call on input focus.

## Accessibility Contract

All form controls require visible labels, not placeholder-only labels. Use `aria-live="polite"` for:
- Step card transitions (buddy question change, improved sentence appearance, turn completion message)
- Resume notice appearance
- Mission completion message

Use `aria-describedby` for validation errors linked to answer and repeat inputs. Turn progress indicator uses `aria-label="Turn {current} of {total}"` on the progress bar element. The progress bar uses `role="progressbar"` with `aria-valuenow`, `aria-valuemin="1"`, and `aria-valuemax="{total}"`.

Hint reveal follows disclosure pattern: the hint button uses `aria-expanded="false"` initially, toggling to `"true"` as each tier is revealed. Each hint tier is in a container with `aria-hidden="true"` until revealed.

Assignment list items that are interactive (Start/Continue) use `role="link"` or are rendered as `<a>` elements. Non-interactive items (Done/Closed) are rendered as `<div>` elements, not buttons or links.

Status badges use visible text labels; color is never the only indicator of status. The Success green, accent blue, and muted gray badges all have distinct text labels ("Done", "Start", "Closed").

All buddy speech and improved sentence areas are standard text content, readable by screen readers in document order. The buddy label "Coco asks:" provides context before the question text.

## Out Of Scope For This UI Contract

Do not design or implement: voice recording or microphone UI (Phase 5), real AI evaluation or AI-generated buddy responses (Phase 6), teacher review dashboards or attempt detail views (Phase 7), auto-miss status mutation (Phase 7), character picker or multi-character selection UI (v2), scoring, grades, leaderboards, progress rings, streaks, or gamification elements of any kind.
