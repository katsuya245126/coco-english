Close the loop. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> completeMissionAction | The client requests completion, but the server independently re-derives completeness from the DB turns; the client cannot force completion |
| completeMissionAction -> service-role status write | The audited started->completed transition bypasses RLS; ownership + legal-transition checks are mandatory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-15 | Tampering | client forcing completion before required turns are done | mitigate | completeAttempt re-derives completeness server-side via isAttemptComplete from the DB turns; a false result writes nothing (D-06, FLOW-06) |
| T-04-16 | Repudiation | completion without an audit trail | mitigate | The started->completed transition always writes an assignment_status_events row (actor_type='student_session', reason_code='mission_completed') before stamping fields (DATA-02 posture) |
| T-04-17 | Tampering | double-complete creating duplicate audit events | mitigate | Conditional UPDATE `WHERE status='started'` returns 0 rows on the second call -> idempotent success, no duplicate event (Pitfall 3) |
| T-04-08 | Tampering | resume spawning a duplicate attempt | mitigate | Resume reuses the in_progress attempt (plan 03 startOrResumeAttempt); the shell never starts a new attempt on return (D-04) |
| T-04-01 | Tampering | AI-06 erosion in the completion/transition screens | mitigate | Completion/transition copy is static; no AI import; `ai-boundary.test.ts` covers the component dir (D-09) |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (RESEARCH Package Legitimacy Audit: zero new packages) |

No `high` threat is left unmitigated.

**Schema push:** Not required. This plan writes only to pre-existing tables (`attempts`, `assignment_students`, `assignment_status_events`) and adds no `supabase/migrations/*.sql` file.
</threat_model>
