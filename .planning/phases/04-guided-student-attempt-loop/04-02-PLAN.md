<objective>
Deliver the student home assignment-list vertical slice end-to-end: the SSR home page reads this student's `assignment_students` rows (joined to `assignments` for title, due_at, snapshot) via the service-role client behind the unlock-cookie gate, computes a read-time display status (Start / Continue / Done / Closed-Expired), and the shell renders one tappable card per assignment with the correct badge — Start/Continue launch the mission route, Done/Closed do not. Empty roster falls back to the existing "No homework yet" copy.

Purpose: After this slice a real student who has been assigned homework can SEE it on their home screen with a clear per-item state and can launch an open mission — the first user-visible capability of Phase 4 (FLOW-01, PILOT-01, D-13/D-14).
Output: `assignment-list.ts` service, `AssignmentListItem.tsx`, extended `StudentHomeShell.tsx` + `home/page.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> SSR home page | Student device requests their home; identity comes only from the unlock cookie, not a client-supplied id |
| SSR -> Supabase (service-role) | The service-role read must be scoped to the unlocked student, never to arbitrary student_ids |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Elevation of Privilege | listStudentAssignments student scoping | mitigate | The query filters `student_id = unlock.studentId` from the cookie; the page never accepts a client-supplied studentId (V4 Access Control) |
| T-04-04 | Information Disclosure | service-role client reaching the browser | mitigate | `assignment-list.ts` imports `createSupabaseServiceClient` from `@/lib/supabase/server` (server-only) and is consumed only by the SSR page; grep gate asserts no `"use client"` in home/page.tsx |
| T-04-05 | Spoofing | enumerating other students' assignments via the home route | mitigate | No id is taken from the request; the unlock cookie is the sole identity source (V3 partial session, Phase 2) |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (RESEARCH Package Legitimacy Audit: zero new packages) |

No `high` threat is left unmitigated.

**Schema push:** Not required. This plan reads only pre-existing tables (`assignment_students`, `assignments`) and adds no `supabase/migrations/*.sql` file.
</threat_model>
