# Phase 10 — UI Design Contract: Mascot (VN-style)

> Visual and interaction contract for the persistent VN-style mascot stage. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled inline `React.CSSProperties` tokens, no Tailwind/shadcn in this codebase |
| Preset | not applicable (no `components.json`, no `tailwind.config.*` found in repo) |
| Component library | none (plain React 19 + Next.js 15, no Radix/Base UI) |
| Icon library | inline hand-drawn SVG (see `SpeakerIcon` in `CocoSpeechAudio.tsx`) — same pattern for any new mascot icon |
| Font | system font stack (no override in `layout.tsx`/globals) — do not introduce a webfont this phase |

**Note on shadcn gate:** This project has no `components.json` and does not use Tailwind — its existing, working design system is a single token file (`src/components/student/styles.ts`) of exported `CSSProperties` constants, consistently reused across 09 phases. Introducing shadcn mid-milestone (82% through v2.0, Phase 12 already scheduled as the dedicated UI-overhaul phase) would be a scope-inflating architectural change explicitly out of bounds for a "wiring, not art authoring" phase (10-CONTEXT.md). Decision: **extend `styles.ts`, do not initialize shadcn.** Phase 12 (UI Overhaul) is the correct place to revisit tooling.

## Mascot Stage Contract (phase-specific)

This section extends the base template with the concrete visual/interaction contract MASCOT-01 through MASCOT-04 require. It is the primary artifact the planner/executor will build against.

### Layout (MASCOT-01)

- **Mount point:** `MissionFlowShell` render tree, ABOVE the existing single-step-card area (`src/components/student/MissionFlowShell.tsx` lines ~591-625). Persistent across all `FlowStep` values (`question`, `aiFeedback`, `repeat`, `repeatFeedback`, `transition`, `complete`, `reviewPending`) — never unmounts between steps (D-01).
- **Stage composition (top to bottom):**
  1. Background scene layer (fixed gradient backdrop, see Color section) — fills stage width, fixed aspect ratio.
  2. Mascot sprite — waist-up, horizontally centered, anchored to stage bottom (sprites are already waist-up-framed portrait PNGs at native ~1792×2389px; render at a fixed max-height so it never crowds the step card below).
  3. Dialogue box — an additive frame overlapping the bottom ~15-20% of the stage (VN convention: box sits over the lower portion of the character art), containing only the speaker-name label. Existing step-card text is unchanged and renders below/within the current step card as it does today (D-02).
- **Stage max width:** matches existing content constraint, `420px` (`panelStyle.maxWidth`) — the stage is not full-bleed; it lives inside the same mobile-first column as the rest of the flow.
- **Stage height:** fixed aspect ratio container (recommend 4:3 or 1:1, planner's call) sized so mascot + dialogue box + at least one step card fit in a single mobile viewport without excessive scroll — do not let the stage push the actionable step card below the fold on a typical phone screen (~700px viewport height minimum assumption).
- **No layout shift between steps:** stage dimensions stay constant; only sprite/expression and dialogue label content change.

### Expression States (MASCOT-03)

Exactly 5 states in scope, mapped 1:1 to already-committed sprites and already-computed flow signals — no more may be added this phase (hard MASCOT-04 ceiling):

| State | Sprite file | Triggered by |
|-------|------------|--------------|
| idle | `coco-neutral-alpha.png` | Default/between actions; also the future host for Phase 11's "Coco is thinking…" (D-12) — keep this state's slot addressable, do not hardcode it as unreachable |
| speaking | (idle/neutral sprite + amplitude-driven animation layer, NOT a separate static sprite) | `CocoSpeechAudio` reports `playing` + amplitude > silence threshold (D-03/D-04) |
| happy/celebrating | `coco-happy-alpha.png` (turn-level accept) / `coco-celebrate-alpha.png` (mission complete) | `acceptedOriginal`, `repeatAccepted` outcomes; `coco-celebrate-alpha.png` reserved specifically for the `complete` step, `coco-happy-alpha.png` for in-flow accepted turns |
| encouraging/neutral (miss) | `coco-encouraging-alpha.png` | `needsCorrection`, `retryOriginal`, `repeatRetry`, forced-retry-on-1-star paths — never a sad/punishing expression (no-harsh-failure principle, MASCOT-03) |
| (reserved, not used this phase) | `coco-thinking-alpha.png`, `coco-sad-alpha.png`, `coco-surprised-alpha.png` | Explicitly OUT of the fixed 3-5 set for Phase 10. `coco-thinking-alpha.png` is earmarked for Phase 11's chat "thinking" indicator (D-12) — do not wire it here, just don't block its future use. `coco-sad-alpha.png` must NOT be used per the no-harsh-failure principle — "encouraging," never "sad," on any miss. |

This yields **4 distinct static sprites in active rotation this phase** (idle/neutral, happy, celebrate, encouraging) plus one **behavioral** state (speaking = amplitude animation over the current expression, not a 5th sprite) — within the "3-5 states" ceiling from MASCOT-03/ROADMAP.

### Speaking Animation (MASCOT-02)

- **Signal source:** Web Audio `AnalyserNode` reading amplitude off the `<audio>` element already owned by `CocoSpeechAudio` (per D-04's recommended default — do not lift audio to a shared shell-level element this phase unless research proves the per-step subscription can't bridge).
- **Visual expression of "speaking":** a lightweight, non-lip-sync animation tied to amplitude — acceptable v0 approaches (planner's choice, in order of simplicity): (a) a subtle scale/bounce pulse on the sprite scaled by amplitude, (b) a simple mouth-open/closed 2-frame swap if a mouth-only overlay is trivially producible, (c) a glow/highlight ring pulsing on the dialogue box. Do NOT build phoneme/viseme lip-sync (explicitly out of scope, REQUIREMENTS.md "Out of Scope").
- **Idle-to-speaking transition:** must be visually distinct at a glance — a static idle sprite vs. any-amplitude-driven motion is sufficient distinction; no minimum animation duration required beyond "not a timer."
- **Below-threshold silence:** brief pauses in speech (natural silence within a sentence) should not flicker the animation off and on — apply a short hold/smoothing window (recommend 150-250ms hysteresis) so the speaking state doesn't visually stutter on every micro-pause.

### Performance Degrade (MASCOT-04, D-07)

- **Trigger:** any device/performance signal indicating the amplitude animation is too heavy (planner determines detection method — e.g. a simple frame-time budget check, or user-agent/heuristic low-end detection consistent with existing "Chromebook/older tablet" language from Phase 8).
- **Degraded behavior:** expression sprite still swaps correctly on state change (idle/happy/celebrate/encouraging) — ONLY the per-frame amplitude animation is dropped. The mascot still visually reflects speaking-vs-not (e.g. static "speaking-adjacent" cue) even in degraded mode if trivial, but a plain static sprite with no animation is an acceptable minimum.
- **Never blocks the flow:** the mission flow (recording, submitting, advancing turns) must work identically regardless of mascot render performance — mirrors Phase 8's "voice degrades, homework loop never blocks" principle verbatim.
- **No error copy:** degrade is silent to the student — no "mascot failed to load" message ever appears (Copywriting Contract, above).
- **Reduced motion (discretionary, recommended):** honoring `prefers-reduced-motion: reduce` by skipping straight to the static-sprite degrade path is a reasonable accessibility addition layered on top of D-07's existing fallback — not required, but low-cost to add since the degrade path already exists.

### Asset Scope Ceiling (MASCOT-04)

- **Sprites in use this phase:** 4 of the 7 committed alpha-cut PNGs (`coco-neutral-alpha`, `coco-happy-alpha`, `coco-celebrate-alpha`, `coco-encouraging-alpha`). No new art generation, no new sprite files, no per-scene background variants.
- **Background:** one fixed CSS gradient (no image asset) — zero new files.
- **Authoring pipeline:** static sprites only (v0, per ROADMAP's explicit acceptance) — the Rive-vs-static-sprite spike is a planning-time research task that precedes this contract; this spec assumes static sprites win by default unless the spike concludes otherwise, per D-04/research flag in 10-CONTEXT.md and ROADMAP.md.
