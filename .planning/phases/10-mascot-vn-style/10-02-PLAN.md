<objective>
Additively attach a Web Audio `AnalyserNode` to the `<audio>` element already owned by `CocoSpeechAudio`, and expose two new optional callback props — `onAmplitudeFrame(level)` and `onPlayingChange(playing)` — that a shell-level `MascotStage` will subscribe to. This is the MASCOT-02 amplitude seam (D-03), implemented via D-04's recommended-default wiring seam (keep `CocoSpeechAudio` owning its per-step `<audio>`; bridge amplitude via a callback prop, not Context/DOM-lifting) — the per-step-subscription bridge RESEARCH §2 confirms viable.

Purpose: Drive the mascot's speaking state from the REAL audio-playback clock (Web Audio amplitude), never a timer and never viseme lip-sync (D-03, LOCKED). The change is strictly ADDITIVE: the existing autoplay/replay/error/degrade branches (the load-bearing Phase 8 playback path) are untouched, so a mascot-analyser failure can never regress Coco's voice.

Output: `CocoSpeechAudio.tsx` with a WeakMap-cached source node, an `AnalyserNode`, a `requestAnimationFrame` amplitude loop that runs only while playing, and the two new callback props — plus a manual audio-not-silent checkpoint (the one thing that cannot be unit-tested).
</objective>
