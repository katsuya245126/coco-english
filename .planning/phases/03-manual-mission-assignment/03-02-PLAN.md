<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teacher browser -> assign server action | Untrusted mission id, class id, and due date cross into assignment creation. |
| assign server action -> Supabase RPC | Server-owned snapshot and assignment request crosses into database transaction. |
| RPC -> teacher-owned tables | Function runs as SECURITY DEFINER and must enforce caller ownership explicitly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | `assignMissionAction` | mitigate | Validate mission id, class id, and nullable due date with Zod; server reads mission/turn rows and builds snapshot per D-05/D-07. |
| T-03-05 | Elevation of privilege | `assign_mission_to_class` RPC | mitigate | RPC checks `current_teacher_id()` owns both target class and mission before inserting, with tests asserting both checks. |
| T-03-06 | Repudiation | Assignment status creation | mitigate | RPC inserts `assignment_status_events` for every created `assignment_students` row with actor `system` and reason `assignment_created`. |
| T-03-07 | Denial of service | Non-atomic multi-row assign | mitigate | Use one Postgres RPC transaction; no separate network calls for assignment and per-student rows. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan; Package Legitimacy Audit says no new packages are introduced. |
</threat_model>
