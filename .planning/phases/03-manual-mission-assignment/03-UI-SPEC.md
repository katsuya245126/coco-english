## Phase 3 Screen Contracts

### Mission List

Add a "Missions" section to the existing teacher dashboard or as a dedicated route (e.g. `/teacher/missions`). The mission list follows the same pattern as the class list: repeated rows on a white surface with `1px #E5E7EB` separator borders.

Each mission row shows:
- Mission title (Text primary, 16px, weight 400)
- Level badge (Label size, Text secondary, no background color — just text)
- Turn count (Label size, Text secondary, e.g. "3 turns")
- Assignment count if any (Label size, Text secondary, e.g. "2 assignments")
- Edit action (secondary button style)
- Assign action (primary button style, visible only if teacher has at least one class with active students)

Empty state uses the centered layout from Phase 2: Heading "No missions yet", Body "Create your first mission to assign speaking homework to a class.", and a primary "Create mission" button.

The page header includes a "Create mission" primary button aligned right, consistent with the "Create class" button on the dashboard.

### Mission Builder (Create and Edit)

The mission builder is a single-page form at `/teacher/missions/new` (create) or `/teacher/missions/[id]` (edit). Use the same layout shell as the teacher dashboard: 56px top bar, 1120px max-width content area, `#F7F8FA` background.

The form is divided into two visible sections on a single scrolling page:

**Section 1: Mission Details**

A white panel (`#FFFFFF`, `1px #D1D5DB` border, `8px` radius, `24px` padding) containing:

| Field | Type | Width |
|-------|------|-------|
| Title | text input | full width |
| Target pattern | text input | full width |
| Topic | text input | full width |
| Level | select/dropdown | half width or 200px min |

Level options are a constrained set. Use a native `<select>` or a custom dropdown. The exact labels are at planner discretion, but must be an enum, not free text. Recommended: "Beginner", "Elementary", "Intermediate".

**Section 2: Turns**

A white panel with section heading "Turns" (Heading size) and an "Add turn" secondary button.

Each turn is a numbered sub-block within the panel, separated by `1px #E5E7EB` borders. Turn numbering is displayed as "Turn 1", "Turn 2", etc. in Label style.

Each turn sub-block contains:
- Turn number header (Label, e.g. "Turn 1") with a "Remove turn" destructive text button aligned right
- Buddy question (text input, full width)
- Target-form example (text input, full width)
- Hint tier 1: Target pattern (text input, full width)
- Hint tier 2: Word bank (text input, full width)
- Hint tier 3: Full example (text input, full width)

Hint fields are grouped under a "Hints" sub-label (Label size, Text secondary). All three tiers are required per turn.

The form footer is sticky or at the bottom of the scrolling page, outside the panels, with:
- Cancel (secondary button, navigates back to mission list)
- Save mission (primary button, right-aligned)

When editing a mission with active assignments, show the warning notice (Warning color `#B45309`, 14px, with a warning icon or bold prefix) between the page title and the first form section: "This mission has {N} active assignment(s). Edits apply to future assignments only; existing homework is unchanged."

**Validation behavior:** Field-level validation errors appear beneath the relevant field in 14px Label style, `#B42318` color. The save button is never permanently disabled; users can submit and see precise validation. The save button shows a loading state while submitting (text changes to "Saving..." and button is disabled).

**Mobile layout:** On screens below 640px, all fields stack full-width. The level select is full-width. Turn sub-blocks remain full-width stacked. The form footer is full-width with buttons stacked (Save mission on top, Cancel below).

### Assign Dialog

Assigning a mission opens a modal dialog (same overlay and panel pattern as Phase 2 dialogs: fixed overlay `rgba(17,24,39,0.45)`, white panel, `8px` radius, `24px` padding, max-width `480px`).

Dialog contents:
1. Title: "Assign mission" (Heading)
2. Mission title displayed as read-only text (Body, Text primary)
3. Class selector: a `<select>` dropdown listing the teacher's classes that have at least one active (non-archived) student. If no classes qualify, show "No classes with active students" in Text secondary and disable the assign button.
4. Student count: after class selection, display "{N} active student(s) will receive homework" in Label style, Text secondary.
5. Due date: an optional date input with label "Due date (optional)" and help text "Leave blank for no deadline. Students can complete anytime." in 14px Text secondary.
6. Footer buttons: Cancel (secondary) and "Assign homework" (primary), right-aligned.

After successful assignment, close the dialog and show an inline success message (Success color `#177245`, 14px) on the mission list or builder page: "Homework assigned to {class name}. {N} student(s) will see it on their next visit." The success message auto-dismisses after 5 seconds or on user interaction.

### Navigation Update

The teacher dashboard top bar or navigation area must provide access to both "Classes" and "Missions". Implementation options (at planner discretion):
- Two text links or tabs in the top bar
- A simple navigation row below the top bar

Do not build a sidebar. Keep navigation minimal: Classes and Missions are the only two destinations in Phases 2-3.

## Interaction States

| Component | Required States |
|-----------|-----------------|
| Buttons | default, hover, focus-visible, disabled, loading |
| Inputs | default, focus-visible, invalid, disabled |
| Select/dropdown | default, focus-visible, invalid, disabled |
| Mission list | loading, empty, populated |
| Mission builder form | idle, submitting, saved, validation-errors |
| Turn sub-block | default, removing (inline confirmation), removed (animated out or instantly removed) |
| Assign dialog | idle, class-selected (shows student count), submitting, success, no-eligible-classes |
| Edit-after-assign notice | visible (Warning color) when mission has active assignments, hidden otherwise |

Focus rings use `#2563EB` at 2px with 2px offset (consistent with Phase 2). All dialogs close on Escape and include a visible close control. Success messages use `aria-live="polite"`. Validation errors use `role="alert"` or `aria-describedby` on the relevant field.

## Layout And Responsiveness

Continue the Phase 2 app shell: top bar 56px, content max-width 1120px, horizontal padding 16px mobile / 24px tablet / 32px desktop.

Teacher desktop breakpoints:

| Range | Contract |
|-------|----------|
| `<640px` | Single-column, full-width form fields, stacked turn blocks, stacked footer buttons |
| `640px-1023px` | Single-column with wider panels, level select may sit beside topic on a two-column row |
| `>=1024px` | Mission builder panels centered at comfortable reading width (max 720px within the 1120px container) |

The mission builder does not need a two-column layout. A single scrolling column is simpler and avoids the turn editor becoming cramped.

---

## Accessibility Contract

All form controls require visible labels, not placeholder-only labels. Each form field must have an explicit `<label>` or `aria-label`. Turn number headers provide group context for screen readers. Hint tier fields are labeled distinctly (e.g. "Turn 1: Hint 1 - Target pattern"). Use `aria-live="polite"` for assignment success messages. Use `aria-describedby` for field-level validation errors linked to their inputs. The assign dialog uses `role="dialog"` and `aria-modal="true"`.

Level select must expose options to assistive technology. Date input must support keyboard entry. Turn removal inline confirmation must be keyboard-accessible (Tab to Cancel/Remove, Enter to activate).
