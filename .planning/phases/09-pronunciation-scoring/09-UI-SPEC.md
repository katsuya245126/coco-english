# Phase 09 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — project deliberately uses plain inline `React.CSSProperties` objects, no Tailwind/shadcn/CSS framework (confirmed: no `components.json`, no `tailwind.config.*`, no `postcss.config.*`, no `*.css` files anywhere under `src/`) |
| Preset | not applicable |
| Component library | none (hand-rolled). Shared style tokens live in `src/components/student/styles.ts` (student surfaces) and inline `React.CSSProperties` const blocks colocated per teacher page/component |
| Icon library | none — no icon library installed; UI uses text/emoji-free copy and CSS shapes only. Stars (D-03) must be rendered as text glyphs (`★`/`☆`) or inline SVG, not an icon-font dependency |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (from `src/app/teacher/evidence/[attemptId]/page.tsx` `shellStyle`) |

This phase does **not** introduce a design system. It extends the existing hand-rolled token set with two new additive UI surfaces: a student-facing star band (in `StepAiEvaluationFeedback.tsx`) and a teacher-facing collapsed diagnostic panel (in the evidence page). Both must reuse existing tokens below — no new colors, spacing values, or font sizes are introduced.

## Spacing Scale

Declared values (must be multiples of 4) — extracted from existing `styles.ts` / evidence page usage, not newly invented:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/star gaps, tight label-to-value spacing (e.g. `margin: "0 0 4px"`) |
| sm | 8px | Compact spacing (`margin-bottom: 8`, gap between hint tiers) |
| md | 12px | Card-internal gaps (annotation grid, audio list gap) |
| lg | 16px | Default card padding, section spacing (`stepCardStyle`, `evaluationSuccessStyle` padding) |
| xl | 24px | Page/panel padding (`panelStyle`, `turnCardStyle`, `summaryStyle` padding) |
| 2xl | 32px | Page-level main content padding (evidence page `mainStyle`) |

Exceptions: minimum interactive control height is 44px (existing `primaryButtonStyle`, `inputStyle`, hint-reveal button) — the diagnostic-panel toggle button (D-05) must also meet this 44px minimum touch target even though it sits inside a dense teacher-facing card.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label / caption | 14px | 600 (semibold) | 1.4 |
| Heading (inline, per-turn/per-card) | 20px | 600 (semibold) | 1.25 |
| Display (page title) | 28px | 600 (semibold) | 1.2 |

Exactly 2 weights used project-wide: 400 (body copy) and 600 (labels, headings, buttons, badges). No 500 or 700 weights appear anywhere in the existing codebase — Phase 9 additions must not introduce a third weight.

New elements this phase must fit into this scale:
- Star band display (student, D-03): render at 20px/600 (matches existing `sentenceStyle`/heading-inline scale) so it reads as a result, not fine print.
- Star band micro-copy ("Great job!" / "Good try!" / "Keep practicing!"): 16px/400, matches `bodyInlineStyle`.
- Diagnostic panel toggle label (teacher, D-05): 14px/600, matches existing `labelStyle` / `AudioClipPlayer.tsx`'s `labelStyle` toggle-adjacent pattern.
- Per-word breakdown entries inside the panel: 14px/400 for word text, existing `annotationLabelStyle` (14px/600, `#6B7280`) for column labels — do not introduce a smaller "fine print" size for phoneme-level data (PRON-F1 deferred; if raw data is stored per Open Question #2 in RESEARCH.md, it must stay unrendered, not shown at a shrunk size).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F8FA` (page background) / `#FFFFFF` (card surfaces) | Page background, card/panel backgrounds |
| Secondary (30%) | `#D1D5DB` (borders), `#4B5563` / `#6B7280` (secondary text) | Card borders, labels, secondary/meta text, dividers (`#E5E7EB`) |
| Accent (10%) | `#2563EB` (blue) | Reserved list below — extends existing usage, does not introduce a new accent hue |
| Destructive | `#B42318` / `#DC2626` (error text/background family: `#FEF2F2` bg, `#FCA5A5` border, `#B91C1C`/`#B42318` text) | Destructive/error states only (existing `evaluationErrorStyle`, `errorTextStyle`, `badgeLateStyle`) |

Accent (`#2563EB`) reserved for: primary CTA buttons (`primaryButtonStyle`), primary nav/text links (`HoverLink` default), the progress-bar fill (`progressFillStyle`), the "start"/"continue" status badges. **This phase does not add new accent usage** — the star band and diagnostic-panel toggle must NOT use `#2563EB` as their primary color; see semantic color mapping below.

### Semantic result-color family (existing precedent, reused for stars)

The codebase already has a 3-tier qualitative result-color convention used for `mapMeaningResult`/`annotationValueStyle` and the evaluation-outcome cards. Phase 9's star band and diagnostic panel MUST reuse this exact family — do not invent new hex values:

| Tier | Background | Border | Text | Existing precedent |
|------|-----------|--------|------|---------------------|
| Positive (3★ / "Great job!") | `#F0FDF4` | `#BBF7D0` | `#065F46` / `#177245` | `evaluationSuccessStyle`, `badgeDoneStyle`, `annotationValueStyle` "Yes" case |
| Neutral-good (2★ / "Good try!") | `#FFFBEB` | `#FDE68A` | `#92400E` / `#B45309` | `evaluationReviewStyle`, `badgeRetryStyle` (repurposed for "good, not perfect" tone — NOT the review/warning meaning in this context) |
| Encouraging-low (1★ / "Keep practicing!") | `#FFFFFF` or `#F7F8FA` (neutral, NOT red/error family) | `#D1D5DB` or `#E5E7EB` (neutral) | `#4B5563` (secondary text, not `#B91C1C`/error red) | **New pairing, deliberately distinct from `evaluationErrorStyle`** — D-03 explicitly forbids a "red X" / failure-looking treatment for 1★, so the 1-star band must NOT reuse the red `#FEF2F2`/`#FCA5A5`/`#B91C1C` error family despite it being the "lowest tier" — it must look neutral/calm, never alarming. |

Star glyph color: filled stars use `#F59E0B` (a warm amber, not yet used elsewhere in the codebase — approved single new value because there is no existing "star"/rating precedent to reuse, and amber-gold is the universal encouraging-rating convention distinct from the app's semantic red/green/amber-warning triad). Unfilled stars use `#D1D5DB` (existing border-gray, matches `inputStyle`/`panelStyle` border color — reuse, not new).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Student star band micro-copy (3★) | "Great job!" |
| Student star band micro-copy (2★) | "Good try!" |
| Student star band micro-copy (1★) | "Keep practicing!" (never "Poor" / "Failed" / "Needs work" — D-03 hard constraint) |
| Student star band label (above stars, optional context) | "Your pronunciation:" — plain, no "score" language anywhere in student-facing copy |
| Teacher diagnostic panel toggle (collapsed state) | "Show pronunciation detail" |
| Teacher diagnostic panel toggle (expanded state) | "Hide pronunciation detail" |
| Teacher diagnostic panel — no data available (pre-Phase-9 attempt, D-08) | "Pronunciation detail is not available for this attempt." (plain, factual, not an error — matches existing `unavailableCopy` tone in `AudioClipPlayer.tsx`) |
| Teacher diagnostic panel — scoring failed silently (Open Question #1 recommendation: omit, don't fabricate) | Same as above — a failed/omitted score renders identically to "not available," never a distinct error message that implies something is broken |
| Teacher diagnostic panel section heading | "Pronunciation breakdown" |
| Teacher diagnostic per-word column labels | "Word" / "Result" (mirrors existing `annotationLabelStyle` two-column pattern: e.g. "Meaning result", "Target pattern result") |
| Teacher per-word "what to fix" values (from Azure `ErrorType`) | "Clear" (ErrorType: None), "Skipped" (Omission), "Extra word" (Insertion), "Mispronounced" (Mispronunciation), "Pause" (UnexpectedBreak/MissingBreak), "Flat tone" (Monotone) — plain teacher-facing diagnostic language, not raw Azure enum strings |
| Destructive confirmation | None — this phase introduces no destructive actions (no delete/reset of pronunciation scores in scope) |

Tone rules carried forward from existing app conventions (D-03, and `AudioClipPlayer.tsx`/`audio-evidence.ts` precedent):
- Never show the raw 0-100 Azure score anywhere in the DOM, including teacher view (PRON-04 applies app-wide per Anti-Patterns in RESEARCH.md — teacher sees qualitative word-level detail, not a numeric composite either, to stay consistent with the no-raw-score product stance).
- No red/failure-coded visuals for the lowest student-facing band (1★) — encouraging framing only.
- Teacher-facing "not available" states are neutral/factual, matching existing `unavailableCopy` and `reviewReasonLabel` tone — never phrased as an error.

## Component-Level Implementation Notes (for planner/executor)

These are not part of the formal contract tables above but capture decisions the checker/executor need and that don't fit the template's generic slots:

1. **Star band rendering** — 3 glyphs always shown (never fewer than 3 slots), filled count = star_band value (1, 2, or 3), unfilled remainder shown in `#D1D5DB`. Placed inside the existing per-outcome card (`stepCardStyle` derivatives) in `StepAiEvaluationFeedback.tsx`, below the transcript block and above/alongside the existing meaning/pattern feedback (D-02: one unified feedback moment). Matches `CocoSpeechAudio` inline-icon-button sizing precedent for touch-friendliness (parent buttons are 44px min-height; the star glyphs themselves are decorative and don't need to meet that minimum individually since they're not separately tappable).

2. **Diagnostic panel disclosure pattern** — Follow `HintRevealer.tsx`'s existing toggle convention exactly: a text button (not `<details>`/`<summary>`) with `aria-expanded`, content region toggled via `display: none/block` (not conditional unmounting) with `aria-hidden` on the collapsed container, consistent with the codebase's established a11y pattern (`HintRevealer.tsx` comment: "Disclosure a11y: button aria-expanded toggles, unrevealed tier containers have aria-hidden"). Collapsed by default per D-05 — never auto-expand, never render above/before the transcript block.

3. **Panel insertion point** — Inside `TurnEvidenceSection` in `src/app/teacher/evidence/[attemptId]/page.tsx`, positioned after `AnnotationGrid` and before `AudioClipList` (i.e., grouped with the other "additive AI/diagnostic" content, not interleaved with the raw transcript blocks — transcript blocks stay visually first and uninterrupted per D-05/Phase 5 D-13/D-14 precedent).

4. **Word-level highlight styling inside the panel** — Use the same 3-color semantic family as the star band (positive/neutral/encouraging-low, see Color section) mapped from Azure `ErrorType`: `None` → positive (green family), `Mispronunciation`/`Omission`/`Insertion` → encouraging-low (neutral, NOT red — per D-03's spirit extended to the teacher panel's word list, since teachers already see the raw plain-English `ErrorType` label as color-adjacent text, red is unnecessary alarm for a routine coaching tool), `UnexpectedBreak`/`MissingBreak`/`Monotone` → neutral-good (amber family, "minor issue" tier). This keeps the same three-tier visual language a teacher already reads elsewhere on the page (`annotationValueStyle`'s Yes/Not-clearly/Needs-review coloring) rather than inventing a fourth palette for this one panel.

5. **No new font, no new spacing unit, no new component library** — every value in this document is either a direct reuse of an existing token/pattern or a single explicitly-justified new value (star-glyph amber `#F59E0B`). The checker should treat any additional new hex/px value introduced during implementation as a deviation requiring justification.
