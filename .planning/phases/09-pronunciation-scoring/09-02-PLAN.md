<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated teacher -> pronunciation_scores rows | A teacher must only read scores for clips belonging to their own classes |
| service_role server writes -> pronunciation_scores | Server-only writes (scoring pipeline) must be the only path that inserts scores |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03 | Elevation of Privilege / Information Disclosure | Cross-tenant read: teacher A viewing teacher B's students' pronunciation scores | mitigate | RLS policy uses `public.is_audio_clip_owner` which traces audio_clip_id -> attempt_turns -> attempts -> assignment_students -> assignments -> classes.teacher_id = current_teacher_id(), replicating the exact ownership chain already enforced for audio_clips. |
| T-09-04 | Tampering | Client-submitted or forged pronunciation scores | mitigate | Writes are performed only by the server-role client in 09-05; the RLS `with check` predicate additionally requires ownership, and authenticated teachers get read/limited grants, not unrestricted insert of arbitrary rows. |
| T-09-05 | Information Disclosure | Missing/incorrect grants causing the server-role write to fail silently or the teacher read to be over-broad | mitigate | Grants for pronunciation_scores mirror exactly the existing audio_clips grants for authenticated and service_role; schema test asserts table/constraint presence. |
</threat_model>
