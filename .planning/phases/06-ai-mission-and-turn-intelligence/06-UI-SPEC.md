## Phase 6 Screen Contracts

### Teacher Mission Builder - AI Draft Panel

Add an AI draft panel to the existing teacher mission builder surface. It must reuse the Phase 3 teacher page shell: `#F7F8FA` background, `1120px` max-width content, `32px` desktop padding, white panels with `1px #D1D5DB` border and `8px` radius.

The AI panel sits above the manual "Mission details" panel on create flow. The existing manual form remains usable if AI generation fails.

Panel layout:

1. Heading: "AI mission draft" (Heading)
2. Body copy: "Create a draft from your class target. You can edit everything before assigning." (Body)
3. Source fields: target pattern, topic, level, required turns, due date if this phase exposes due date for generation context
4. Primary action: "Generate draft"
5. Status area: pending, success, failed-schema, or service-failure state
6. Draft preview after success
7. Actions: "Use draft" primary and "Generate again" secondary

Required interaction:

- Teacher can still manually type/edit every mission field after using the draft.
- "Use draft" fills the existing mission form fields rather than creating a hidden assignable mission.
- Generated turns must render in the same order and shape as manual turns: buddy question, target-form example, and three hint tiers.
- Failed schema output must not populate the mission form and must not be assignable.
- AI service failure must keep existing typed form data intact.
- Do not show raw JSON, model names, prompt text, confidence internals, token counts, or stack traces in the UI.

### Draft Preview

The draft preview is a white sub-panel with `1px #E5E7EB` border, `8px` radius, and `16px` padding. It lists:

- Mission title
- Target pattern
- Topic
- Level
- Required turns
- Ordered turn cards

Each turn card uses a compact version of the manual turn editor:

- "Turn {N}" as Label
- Buddy question as Body
- Target-form example as Body with `#F0FDF4` surface only when previewing the generated example
- Hints listed in order as Label + Body rows

The preview is read-only. Editing happens in the existing mission form after "Use draft".

### Student Original Answer Evaluation

After the original transcript is available from Phase 5 transcription, the student flow must show an AI evaluation state before deciding the next step.

State order:

1. Transcript confirmation: "We heard:" plus transcript
2. Pending state: "Checking your answer..."
3. One of four outcomes:
   - Correct English target response: positive reinforcement, no improved sentence, no repeat required for that turn
   - Needs correction: improved sentence card and repeat step required
   - Non-English: error panel and "Record again"; turn does not advance
   - Teacher review routing: warning panel, turn can continue without pretending pass/fail certainty

Correct-answer outcome:

- Use `#F0FDF4` surface and `#BBF7D0` border.
- Heading: "Nice answer!"
- Body: "You used the English practice well. Let's keep going."
- Primary action: "Continue"
- Must skip the improved sentence card and repeat recorder for that turn.

Correction outcome:

- Preserve the existing Phase 4/5 improved sentence layout.
- Heading copy: "Nice try! Here is a clearer way to say it:"
- Improved sentence card uses `#F0FDF4` and `#BBF7D0`.
- Repeat remains required before the turn can continue.
- Only show an improved sentence when evaluation says correction is needed.

Non-English outcome:

- Use `#FEF2F2` surface and `#FCA5A5` border.
- Heading: "Try that in English."
- Body: "Record your answer again using English."
- Primary action: "Record again"
- Do not mark the turn accepted, do not show an improved sentence, and do not route as a successful answer.

Teacher-review routed outcome:

- Use `#FFFBEB` surface and `#FDE68A` border.
- Heading: "Your teacher will check this answer."
- Body: "Keep going. Your teacher can review this turn later."
- Badge: "Teacher review"
- The UI must not label this as correct or wrong.
- If the app lets the student proceed, the interaction copy must make clear that the teacher will review it later.

### Student Repeat Evaluation

When an improved sentence is required, the repeat step stays voice-first:

1. Show original transcript.
2. Show improved sentence.
3. Show repeat recorder.
4. Show "Checking your repeat..." after repeat transcription.
5. If repeat is accepted, show "Good repeat." and continue.
6. If repeat is not close enough, show "Try the repeat again." plus "Listen to the sentence and record it one more time."
7. If repeat evaluation is low-confidence, route to teacher review rather than showing pass/fail certainty.

Do not show numerical scores, pronunciation percentages, grades, rankings, or complex grammar explanations.

### Teacher Evidence Additions

Phase 6 may annotate existing teacher attempt evidence rows with AI evaluation fields, while full dashboard buckets remain Phase 7.

If shown in Phase 6, each turn section displays:

- Original transcript
- Meaning result: "Understood", "Needs teacher check", or "Try again"
- Target pattern result: "Target pattern used", "Target pattern missing", or "Needs teacher check"
- Improved sentence only when a correction was needed
- Repeat transcript when present
- Repeat result: "Accepted", "Try again", or "Needs teacher check"
- Review badge and reason when low-confidence, ambiguous, malformed, or failed-schema output was routed to teacher review

Teacher evidence remains transcript-first. Audio playback remains on-demand only, following Phase 5.

## Accessibility And Interaction Rules

- Use real `<button>`, `<input>`, `<select>`, and `<textarea>` elements.
- All controls must preserve the global focus ring: 2px solid `#2563EB` with 2px offset.
- Generation and evaluation status changes use `aria-live="polite"`.
- Non-English, failed-schema, service-failure, and retry-blocking errors use `role="alert"`.
- Do not rely on color alone. Every success, warning, review, and error state must include visible text naming the state.
- Student screens remain one focused step card at a time; do not convert the flow into a chat transcript.
- Teacher generated draft preview must be keyboard navigable in source order.
- Loading states must not remove existing user-entered form content.

---

## Prohibited UI

- No open-ended chat box.
- No autonomous live voice agent.
- No raw AI JSON, prompts, model identifiers, token counts, or confidence decimals in child-facing UI.
- No numerical grades, pronunciation percentages, class ranking, leaderboards, or score badges.
- No correction shown when the student's original English answer is already correct.
- No accepting non-English responses as successful English practice.
- No auto pass/fail display for low-confidence, ambiguous, malformed, or failed-schema AI output.
- No new design system, component registry, icon dependency, or Tailwind/shadcn setup in Phase 6.
