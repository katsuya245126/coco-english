<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TTS service -> database | Service-role writes cache metadata guarded by app logic. |
| TTS service -> Storage | Generated audio enters a private bucket and is exposed only by signed URLs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure / Elevation of Privilege | Server-only OpenAI usage | mitigate | Schema plan creates only DB/Storage; later plans keep provider access in server modules. |
| T-08-02 | Denial of Service / Abuse | Arbitrary paid TTS generation | mitigate | Cache table is keyed by server-computed `content_hash`; no trusted client hash column is accepted. |
| T-08-03 | Tampering | Cache-key metadata | mitigate | Unique `content_hash` and immutable object keys prevent duplicate regenerated rows for identical input. |
| T-08-04 | Information Disclosure | Unauthorized assignment audio lookup | mitigate | Table grants are service-role only; browser cannot directly select cache rows. |
| T-08-05 | Information Disclosure | Storage exposure | mitigate | `tts-audio` bucket is private; no public Storage policy or public URL is introduced. |
| T-08-06 | Denial of Service | Provider failure blocking homework | mitigate | Schema is additive; later route returns non-blocking errors without status mutations. |
| T-08-07 | Information Disclosure / Elevation of Privilege | Client OpenAI imports | mitigate | No client files are modified in this plan; Wave 0 source-boundary tests enforce this later. |
| T-08-SC | Tampering | npm installs | accept | No package-manager install tasks in this plan. |
</threat_model>
